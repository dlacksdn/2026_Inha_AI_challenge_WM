## 1. 무엇을 물었나

016 §9.2 가 잔차 노선의 천장과 바닥을 쟀다. 이득의 출처가 뜻밖이었다 — DINO 가 아니라 Video 였다.

```
  뭉갠 잔차 4배 α=1 을 배점까지 곱해 분해하면
    DINO    0.3 × (0.15664 − 0.12308) = +0.01007   ← 손해 (뭉개면 장면이 더 틀려 보인다)
    Video   0.3 × (0.02297 − 0.09110) = −0.02044   ← 이득
    Action  0.4 × (1.22386 − 1.24017) = −0.00652   ← 이득
                                        ─────────
                                         −0.01690
```

그래서 자연스러운 질문이 나왔다. **DINO 손해는 "잔차를 더하면 뭉개진다"에서 온다.
픽셀을 옮기기만 하면(워핑) 그 손해가 없어지지 않을까?**

```
  덧셈 잔차   출력 = 첫프레임 + 잔차
      단점: 모델이 만드는 잔차는 저주파라 디테일이 흐려진다 (실측 DINO +0.010)

  워핑        출력 = 첫프레임의 픽셀을 흐름대로 밀어 옮긴 것
      장점: 원본 픽셀을 그대로 옮기므로 디테일이 안 뭉개진다   ← 이 가설을 검증한다
      단점: 가려졌다 드러나는 자리를 못 채운다
```

⚠ **"디테일이 안 뭉개진다"는 우리 구현에서 성립하지 않는다** (2차 검수).
`grid_sample(mode="bilinear")` 은 변위가 정수가 아닌 **모든 화소**에 저역통과를 건다.
§4.2 가 잰 바로 σ=0.5px 흐림만으로 DINO 가 +0.00193 오르므로,
**워핑의 DINO 손해 중 상당 부분이 보간 흐림일 수 있다.**
(`warp:0` 새너티는 이걸 못 잡는다 — α=0 이면 격자가 정수 위치라 보간이 안 일어난다.)
3라운드에서 `mode='nearest'` 로 분리한다. **다만 판정은 안 뒤집힌다** — 워핑이 지는 곳은
Video(배점곱 +0.00938)이고 DINO 를 전부 회복해도(0.3×0.0266 = 0.0080) Gate 0 의 +0.01247 에
못 미친다.

어느 단점이 큰지는 **로봇 팔이 화면에서 차지하는 면적과 배경의 복잡도**에 달렸고,
그건 우리 데이터에만 있는 정보다. 문헌은 일반론만 준다(017 §6.3 이 확인했다).

## 2. 판정선을 결과 전에 고정했다 — 그리고 그 중 하나는 틀렸다

016 §7-3 의 교훈: 판정선을 결과 본 뒤에 정하면 '조금만 더' 편향이 생긴다.

| 게이트 | 비교 | 무엇을 뜻하나 |
|---|---|---|
| **0. 킬스위치** | `warp:1` vs `addblur4:1` | 흐름이 **완벽해도** 뭉갠 덧셈을 못 이기면 워핑은 표현력 자체가 부족한 것 |
| **1. 현실적 천장** (주) | `warpc4:1` vs `addblur4:1` | 둘 다 4배로 뭉갠 짝. 모델이 실제로 만들 수 있는 것끼리 |
| **2. 바닥** (보조) | `warpnbr:α` vs `addnbr:α`, α∈{0.25,0.5,1} | 방향이 틀렸을 때 누가 덜 다치나 |

```
Gate 0   Δ₀ ≥ 0 이고 t₀ ≥ +2        →  워핑 폐기. Gate 1·2 무관하게 덧셈 확정
Gate 1   Δ₁ ≤ −0.005 이고 t₁ ≤ −2   →  워핑 유리
         Δ₁ ≥ +0.005 이고 t₁ ≥ +2   →  덧셈 유리
         그 외                       →  무승부
Gate 2   세 α 전부 부호가 같아야 인정한다
최종     Gate 0 발동 → 덧셈 / Gate 1 워핑유리 & Gate 2 불리아님 → 워핑
         Gate 1 무승부 & Gate 2 워핑유리 → 워핑 / 그 외 → 덧셈(동점은 단순한 쪽)
```

**0.005 를 고른 근거 둘 중 하나는 틀렸다.** 미리 적어 두고 나중에 검증한 덕에 잡혔다.

| 근거 | 내용 | 사후 검증 |
|---|---|---|
| ① 의사결정 무차별 구간 | 덧셈 노선의 현실적 이득 전체가 −0.0169 인데, 그 30% 도 안 되는 차이로 구현 복잡도를 2배 올릴 수 없다 | **타당하다.** 통계가 아니라 선호 선언이고, 사전에 고정했으므로 정당하다. 실제로 §3.8 에서 값을 했다 |
| ② 통계적 분해능 | 짝지은 DINO 차이 SE=0.00834 → TOTAL 환산 0.3×0.00834≈0.0025, 즉 0.005≈2·SE | **틀렸다.** 실측 SE=0.00472 라 2·SE=0.00944 다. 사전 추정이 **3.8배** 빗나갔다 |

②가 틀린 이유가 교훈적이다. `SE(TOTAL) = 0.3·SE(ΔDINO)` 는 **Video 와 Action 의 표본별
차이가 정확히 0일 때만** 성립한다. 그런데 016 §9.2 는 이득의 출처가 Video 라고 스스로
밝혔다 — 즉 **가장 큰 분산 성분을 통째로 빼고** 계산한 것이다.

> **다음부터**: SE 를 사전 추정할 때는 **가장 큰 성분의 분산부터** 센다.

결론은 안 바뀌었다. 게이트가 `|Δ| ≥ 0.005` **와** `|t| ≥ 2` 를 **동시에** 요구하므로 늘
더 엄격한 쪽이 구속하고, Δ=+0.01407 > 0.00944 로 양쪽을 통과했다. **운이 좋았다.**

## 3. 측정 ① — 워핑 vs 덧셈

### 3.1 먼저 결정성 확인 — ⚠ **독립 재현 검증이 아니다** (2차 검수 정정)

이번 측정은 016 §9.2 의 덧셈 변형들을 **같은 실행 안에서 다시 계산**한다.
표본별로 짝짓기 위해서다.

> **처음에는 이걸 "독립 재현 검증"이라 불렀다. 틀렸다.**
> `probe_warp_vs_add.py:107` 이 016 의 `blur_residual` 과 `nearest_by_action` 을
> **그대로 import** 한다. 같은 함수·같은 홀드아웃·같은 `static_preds`·전부 결정론 연산이므로
> **5자리 일치는 필연이지 검증이 아니다.** 016 의 `blur_residual` 에 버그가 있었다면
> 이 "검증"은 100% 통과한다.
>
> 사소하지 않다 — §8.1 의 해상도·흐림 결정이 전부 **`blur_residual` 이 "모델의 저해상도
> 출력"의 타당한 대리값이라는 가정** 위에 서 있는데 그 함수는 한 번도 독립 검증된 적이 없다.
> **3라운드에서 독립 구현(`avg_pool2d` + `nearest` 업샘플)으로 대조한다.**

### 3.5 왜 졌나 — 눈으로 보면 통계보다 명확하다

`artifacts/branchC/20260801_1747_warp_vs_add_frame15.png` (표본 3개 × 프레임 15)

세 표본에서 일관되게 보이는 것:

```
  정답      팔이 위로 빠져나갔다. 원래 팔이 가리던 배경이 **드러났다**
  정지영상  팔이 처음 자리에 그대로
  워핑      팔이 거의 그대로 남아 있다  ← 여기가 핵심
  덧셈      팔이 흐릿하게 **지워지고** 배경이 부분적으로 복원됐다
```

**왜 워핑이 팔을 못 지우나.** 역방향 워핑은 "프레임 t 의 각 픽셀은 프레임 0 의 어디에서
왔는가"를 물어 그 자리의 픽셀을 당겨온다. 그런데 팔이 비켜난 자리의 배경은
**프레임 0 에서 팔에 가려져 있어 화면 어디에도 존재하지 않는다.**
흐름 추정기는 대응점이 없으니 0 에 가까운 값을 내고, 결과적으로 팔이 남는다.

문헌이 이것에 이름을 붙여 뒀다 — SDC-Net 의 **"foreground stretching"**
(017 §6.5). 그리고 이렇게 경고한다: **"backward 워핑은 구멍을 안 남긴다.
대신 조용히 틀린 픽셀을 채운다."** 우리 그림이 그 문장 그대로다.

**흐름 자체는 제대로 일한다.** 3번째 표본(집게가 테이프로 내려오는 장면)에서는
워핑이 집게를 선명하게 잘 내렸다. 문제는 흐름의 품질이 아니라 **표현의 한계**다.

### 3.6 검수가 잡은 것 — 뭉갬 배율 **한 점**에 결론이 걸려 있었다

측정을 돌리는 동안 설계를 적대적 검수에 걸었다. 가장 아픈 지적:

> 사전등록은 k=4 **한 점만** 게이트로 걸었다. 스크립트는 k=8 도 계산해 놓고 게이트에서 뺐다.
> 저장된 rows 로 사후 계산하면:

#### ② ❌ 철회 — "공정한 바닥"이 공정하지 않았다 (2차 검수, 2026-08-01 19:00)

**처음 적었던 것**: 같은 틀린 움직임을 덧셈 표현으로 바꿔 얹어 비교했더니 부호가 뒤집혀
`warpnbr` 이 `addnbrwarp4` 보다 +0.00370 나쁘고(t=+2.54), 따라서
"워핑은 틀려도 덜 다친다"가 폐기되고 **"워핑은 바닥에서도 진다"**가 성립한다고 썼다.

**틀렸다. 두 팔이 지는 것은 같은 오차인데 뭉갬 배율이 다르다.**

```python
  nbr_warp      = warp(첫프레임, 남의흐름,  뭉갬 없음)          # ← warpnbr:1
  addnbrwarp4   = static + blur_4(nbr_warp − static)          # ← 여기만 4배 뭉갠다
```

`blur_residual(x, 1)` 은 항등 연산이므로 `addnbrwarp1 ≡ warpnbr:1` 이다.
즉 내가 잰 Δ=+0.00370 은 **"덧셈 표현이 워핑 표현보다 덜 다친다"가 아니라
"틀린 움직임은 4배로 뭉개면 덜 다친다"** 였다. 표현 비교가 아니라 흐림 비교다.

> **바로 위 §3.7① 에서 "뭉갬 배율이 결론을 좌우한다"를 이 문서의 핵심 교훈으로 세워 놓고,
> 그 교훈을 적용해 만든 수정에서 같은 실수를 다시 했다.**
> 016 §3.7 이 겪은 실수의 **세 번째 얼굴**이다.

**⇒ 바닥은 다시 미측정 상태다.** 구 바닥(`warpnbr` vs `addnbr`)은 장면이 통째로 달라
이미 무효였고, 새 바닥도 무효다. **"워핑은 바닥에서도 진다"를 철회한다.**

**⇒ 그래도 노선 결정은 안 흔들린다.** 판정은 사전 등록한 Gate 0(천장)이 발동해서 내려졌고,
Gate 0 은 이 문제와 무관하다. 바닥은 016 §9.2-c 의 위험구조 논변을 **보강**하는 재료였을 뿐이다.

**재측정 방법** (3라운드에 넣었다): 두 팔에 **같은 배율**을 건다.
`warpnbr_c4 = warp(첫프레임, coarsen_flow(남의흐름, 4), 1)` vs `addnbrwarp4`.

**첫째 — 사전에 적어 둔 판정 기준을 결과를 본 뒤에 바꿨다.**
2라운드 스크립트가 측정 **전에** 이렇게 적어 놨다:

> "프레임별 DINO 를 저장한다. **t 에 따라 손해가 커지면 흐름 품질이 범인**이고,
> t 와 무관하게 평평하면 가림/드러남이 범인이다."

그 기준을 실제 데이터에 적용하면:

```
  워핑의 DINO 손해 (static 대비)
    t=1 +0.0085   t=3 +0.0183   t=6 +0.0323   t=9 +0.0395   t=15 +0.0315
    → t=1 에서 t=9 까지 **4.6배 커진다.**  사전 기준대로면 "흐름 품질이 범인"이다.
```

이 표를 그대로 실어 놓고 **판정 근거를 픽셀 L1 로 갈아탄 뒤 반대 결론을 냈다.**
§2 가 자랑한 "판정선을 결과 전에 고정" 원칙의 정면 위반이다.

**둘째 — 갈아탄 지표도 유리한 쪽으로 읽었다.**

```
  픽셀 L1 (워핑 − 정지영상)     t=3 −1.700 → t=15 −1.462     "14% 줄었을 뿐"
  그런데 정지영상 자체의 L1 은   t=3  6.393 → t=15 11.818     (85% 증가)
  ⇒ 흐름이 지워 준 오차의 **비율**   −26.6% → −12.4%          **반토막이다**
```

절대차는 평평하지만 정규화하면 흐름의 상대 기여가 절반으로 준다.
**결론에 유리한 절대 지표를 택했다.**

> **⇒ "워핑이 진 이유는 표현의 한계다"를 철회한다. 이유는 아직 미확정이다.**

**재측정 방법** (3라운드에 넣었다): 스크립트가 이미 `--flow farneback` 을 지원한다.
RAFT 를 훨씬 약한 추정기로 바꿔 같은 측정을 한다.
**결과가 거의 안 변하면 흐름 품질은 무죄고, 크게 변하면 흐름 품질이 범인이다.**
§3.6 이 스스로 "진짜 독립 축은 뭉갬 배율·**흐름 추정기**·이웃 정의"라고 적어 놓고
이 축만 안 돌렸다.

**⇒ 다만 노선 결정은 안 흔들린다.** 흐름 품질이 범인이라 해도 우리에게는 불리하다 —
우리 모델은 **두 프레임을 다 보는 RAFT 와 달리 첫 프레임과 행동만으로 흐름을 예측**해야
하기 때문이다. RAFT 가 못 푸는 변위를 우리 모델이 풀 이유가 없다.
**이것은 논변이지 측정이 아니므로, 측정으로 확정하기 전까지 논변으로만 취급한다.**

덤으로 보이는 것: **덧셈의 DINO 손해는 t 가 커질수록 줄어든다**(+0.0496 → +0.0130).
초반에는 바뀐 게 적어 뭉갬의 대가가 상대적으로 크지만, 후반에는 실제로 새 내용을
만들어낸 값어치가 커진다. **긴 지평일수록 덧셈이 유리하다.**

#### ④ 새너티 — 좌표 규약은 맞다

```
  warp:0 vs staticexact   성분 **평균**의 차이 7.74e-06   (표본별 최대는 5.96e-04)
  add:1  의 DINO −1.96e-10, Video 4.12e-09   (정답과 같아야 하므로 0)
```

`warp:0` 은 내가 건 문턱(1e-6)을 아슬아슬하게 넘겨 "실패"로 찍혔지만 **실질은 통과다.**
별도로 확인했다 — 무작위 영상에 α=0 워핑을 걸면 **uint8 변환 후 다른 픽셀이 0개**다.
7.74e-06 은 `grid_sample` 의 float32 정밀도이며, 우리가 재는 효과(1e-2)보다 **여섯 자릿수** 작다.

> **문턱이 잘못됐다.** float32 를 통과하는 값에 1e-6 을 요구한 것이 무리였다.
> 다음부터 이런 새너티는 **uint8 픽셀 일치**로 걸어야 한다.

#### ⑤ ⚠ 016 의 **작동점 가정(k=4)이 임의적**이었다 (제목 정정 — 2차 검수)

> **처음에는 "016 의 헤드룸 추정이 2.2배 낮게 잡혀 있었다"고 썼다. 부당한 표현이라 고친다.**
> 016 §9.2 는 천장을 **−0.07121 로 명시**했고, −0.01690 에는 *"뭉갠 잔차 **4배** α=1"* 이라고
> 가정을 라벨에 달았으며 *"천장의 24% 를 건진다"*고도 적었다. 016 이 한 것은
> **작동점 가정**이지 헤드룸 추정이 아니다. 내가 한 것은 **그 가정을 k=4 에서 k=2 로 옮긴 것**이고,
> **k=2 가 도달 가능하다는 근거는 이 문서 어디에도 없다**(아래 ⑤-b).

016 §9.2 는 뭉갬 배율을 **4배와 8배만** 쟀다. **2배를 재니 −0.03798 이다. 4배 값의 2.2배다.**

더 중요한 것은 **성분 분해가 뒤집힌다는 것**이다.

```
  016 §9.2 ② (k=4 기준)                    이번 (k=2 기준)
    DINO   +0.01007  손해                    DINO   0.3×(0.10271−0.12308) = −0.00611  이득
    Video  −0.02044  이득                    Video  0.3×(0.00809−0.09110) = −0.02490  이득
    Action −0.00652  이득                    Action 0.4×(1.22276−1.24017) = −0.00696  이득
           ─────────                                ─────────
            −0.01690                                 −0.03798
```

016 은 이렇게 결론지었다:

> 잔차 노선의 정체는 "장면을 정확히 그린다"가 아니라 **"대충이라도 움직여 Video 를 챙기고
> DINO 손해를 감수한다"** 이다. **DINO 를 지키려 애쓰는 설계는 방향이 틀린 것일 수 있다.**

**이 문장은 k=4 의 산물이었다. k=2 에서는 세 성분이 전부 이득이고 DINO 도 static 을 이긴다**
(0.10271 < 0.12308). **⇒ 016 §9.2 ② 의 설계 함의는 여기서 철회한다.**

새 그림은 훨씬 단순하고 희망적이다.

```
  잔차의 유효 해상도       static 대비 이득
    1/2                    −0.03798     ← DINO 도 이득
    1/4                    −0.01690     ← 016 이 유일하게 잰 점. DINO 손해
    1/8                    −0.00380
    1/16                   −0.00039
    완벽(정답)             −0.07121     (도달 불가)
```

> **해상도가 곧 이득이다.** §4.3 의 흐림 예산(1/2 이상)과 같은 지점을 가리킨다.
>
> ⚠ 처음에는 "두 측정이 **독립적으로** 같은 답을 냈다"고 썼는데 **거짓이다.**
> `coarsen` 은 선형 연산이라 두 측정이 항등식으로 묶여 있다(§4.5 참조).
> 근거는 하나이고 나머지는 그 대수적 따름정리다.

#### ⑤-b ⚠ 그런데 **"오라클 잔차를 1/2 로 뭉갠 것"과 "모델이 1/2 해상도로 낸 잔차"는 같은 물건이 아니다**

2차 검수가 지적한 이 문서의 **가장 약한 고리**다. 그리고 옳다.

```
  addblur2       : 드러난 배경의 저주파 내용이 **정답이다.** 뭉개기만 했지 내용은 맞다
  1/2 잔차 모델  : 그 내용을 **창작해야 한다.** 첫 프레임에 존재하지 않는 픽셀이다
```

**이 구분은 §3.5 가 워핑을 죽일 때 쓴 바로 그 논리다** — *"드러난 자리의 배경은
프레임 0 에 존재하지 않는다"*. **워핑에 적용한 잣대를 덧셈의 헤드룸에는 적용하지 않았다.**

그리고 §4.6 에서 이 등식이 깨지는 자리를 이미 관측해 놓고도 결론에 반영하지 않았다 —
같은 1/2 해상도에서 "전체를 고르게 뭉갠 것"(DINO 0.032)이
"static + 뭉갠 잔차"(DINO 0.103)를 3배 넘게 이긴다. **모델이 만들 잔차의 흐릿함은
후자 쪽에 붙는다.**

> **⇒ −0.03798 은 "우리가 얻을 이득"이 아니라 "잔차를 1/2 해상도로 *정확히* 만들었을 때의
> 오라클 값"이다.** 016 이 k=4 를 "현실적"이라 부른 것과 내가 k=2 를 "도달 가능"이라 부른 것은
> **근거의 급이 같다.** 016 을 비판한 방식과 정확히 같은 종류의 낙관을 반복하지 않기 위해
> 이 절의 결과는 **탐색적**으로만 취급한다.
>
> **진짜로 필요한 측정**은 §9-c 에 적었다 — 방향(α)과 해상도(k)를 **2차원으로** 훑는 것.
> 016 §9.2 가 우리 모델 좌표를 **α≈0.35** 로 못 박았으므로, 물어야 할 질문은
> **"α=0.35 에서 k 를 2 로 낮추면 이득이 남는가"** 이고 이 문서는 그 칸을 비워 뒀다.

### 3.8 혼합(워핑 + 덧셈 보정)은 어떻게 되나

**문헌이 예측한 대로 혼합이 가장 좋다.** 017 §6.1 이 정리했듯 RIFE·EMA-VFI 의 출력식이
문자 그대로 `워핑 + 마스크 + 유계 잔차`다.

```
  warpc4+res4:1  vs addblur4:1   Δ=−0.00445  t=−2.52   65/96
  warp+res4:1    vs addblur4:1   Δ=−0.00923  t=−4.95   73/96
```

**유의하게 이긴다.** 그런데 채택하지 않는다. 이유가 둘이다.

1. **`warp+res4` 는 도달 불가능하다.** 원본 해상도 오라클 흐름을 쓴다. 뭉갠 흐름을 쓰는
   현실적 변형은 `warpc4+res4` 이고 그 이득은 **−0.00445 로 무차별 구간(0.005) 안**이다.
2. **사전 등록한 무차별 규칙이 그대로 적용된다.** 0.005 를 못 넘는 이득으로
   흐름 헤드 + 미분가능 워핑 + 경계 처리 + 항등 붕괴 방어를 추가할 수 없다. 19일뿐이다.

> **그러나 묻어 두지 않는다.** 혼합은 **DINO 축에서 유의하게 이긴다**(Δ=−0.01129, t=−2.21).
> DINO 는 우리가 로컬 −0.069, eval −31% 를 줄여야 하는 바로 그 축이다.
> **DINO 가 병목으로 확정되면 되돌아올 1순위 후보다.**
>
> 되돌아올 때의 설계도 이미 있다(017 §6.5): **흐름 헤드를 zero-init** 하면
> step 0 에서 항등 워핑이라 출력이 정확히 static 이고, 흐름이 끝내 안 배워지면
> **그대로 순수 덧셈 모델로 퇴화한다.** 즉 혼합의 실패 모드가 곧 덧셈 모델이다.
> 하방이 막혀 있다는 점에서 016 §9.2-c 의 논리가 그대로 성립한다.

## 4. 측정 ② — 흐림 세금: 예산이 σ ≈ 1.2~1.9픽셀뿐이다

### 4.1 왜 쟀나

우리가 가려는 결정론 회귀는 **필연적으로 흐릿한 영상**을 낸다. 여러 그럴듯한 미래의
한가운데를 찍기 때문이다(017 §3). 그러면 얼마나 흐려도 되나?

문헌은 "DINOv2 는 흐림에 **비교적** 관대하다"고 말하지만(DreamSim, DINO-IR),
동시에 **약한 흐림에서만** 그렇다고도 한다([arXiv:2401.00463](https://arxiv.org/abs/2401.00463)).
그리고 결정적으로 **우리가 서 있는 지점이 문헌의 지점과 다르다.**

```
  분류 문제의 감각:  코사인 유사도 0.85 면 "확실히 비슷하다"
                    (서로 다른 이미지 쌍이 0.3~0.5 이므로)

  우리의 작동 범위:  같은 장면 이웃 프레임끼리 0.99 근처
                    여기서 0.98 → 0.90 으로 떨어지면 거리는 0.02 → 0.10, **5배**
```

**남의 감각을 옮겨 쓰면 크게 틀린다. 그래서 직접 쟀다.**

### 4.5 §3.7⑤ 와의 관계 — ⚠ **독립이 아니다. 대수적으로 묶여 있다** (2차 검수 정정)

> **처음에는 "독립 측정 둘이 같은 답을 냈다"고 썼다. 거짓이다.**
> 두 측정은 **문자 그대로 같은 연산**(area 축소 + bilinear 확대)을 쓰고, 그 연산이 선형이라
> 항등식으로 묶여 있다:
>
> ```
>   addblur_k = static + coarse_k(gt − static)
>             = coarse_k(gt) + (I − coarse_k)(static)
>               └ §4 의 열 ┘   └ static 의 고주파를 되돌려 주는 항 ┘
> ```
>
> 오른쪽 열은 왼쪽 열의 **함수**다. 같은 96표본·같은 채점기·같은 연산이다.
> **근거는 하나이고 나머지는 그 따름정리다.**

이 절(§4)은 **정답 영상 전체를 흐리게** 해서 잰 것이고,
§3.7⑤ 는 **잔차만 뭉개서** 잰 것이다. 위 항등식으로 이어져 있다.

| 유효 해상도 | 정답 전체를 뭉갤 때 (§4.2) | **잔차만 뭉갤 때** (§3.7⑤) |
|---|---:|---:|
| 1/2 | −0.05849 | **−0.03798** |
| 1/4 | −0.01612 | −0.01690 |
| 1/8 | +0.09506 | −0.00380 |
| 1/16 | +0.21679 | −0.00039 |

```
  1/2~1/4 구간에서는 두 방식이 비슷하다
  1/8 이하에서 **완전히 갈린다** — 전체를 뭉개면 재앙(+0.095)이고 잔차만 뭉개면 그냥 무이득(−0.004)
```

이 갈림은 **발견이 아니라 위 항등식의 자명한 귀결**이다. k 가 커지면 `coarse_k(gt)` 는
쓰레기가 되지만 `(I − coarse_k)(static)` 이 첫 프레임의 고주파를 통째로 되돌려 놓으므로
잔차 쪽은 static 으로 수렴한다.

#### ⚠ 그리고 "하방이 0 으로 막힌다"는 **DV 축에서 성립하지 않는다** (2차 검수)

§3.6 에서 016 §5 를 근거로 "로컬 Action 은 폐기 대상"이라 인정하고 DV 를 신뢰 축으로
선언했다. 그런데 이 절의 "최악이 무이득이다"는 **TOTAL 위에서만 참이다.**

```
  ΔDV (static 대비, 음수여야 이득)
    addblur2  −0.03101 (t=−11.90)      addblur4  −0.01037 (t=−4.15)
    addblur8  **+0.00115**             addblur16 **+0.00598 (t=+3.95)**  ← static 보다 나쁘다

  addblur16 성분 분해:  0.3ΔD = +0.00953   0.3ΔV = −0.00355   0.4ΔA = −0.00637
                        └ TOTAL 이 0 근처(−0.00039)인 것은 **오직 폐기 선언한 Action 덕이다**
```

**⇒ 오라클 잔차의 하방은 0 이 아니라 DV 기준 +0.006(손해)이다.**
"0 으로 막혀 있다"는 그림은 신뢰하지 않기로 한 성분이 만든 착시다.

> **다만 아키텍처의 하방은 여전히 정확히 0 이다.** 이건 다른 이야기다 —
> 잔차 헤드를 zero-init 하면 **잔차가 문자 그대로 0** 이라 출력이 static 과 완전히 같다.
> 위 표는 "오라클 잔차를 거칠게 뭉갰을 때"이고, 그건 학습 실패 시의 상태가 아니다.
> **혼동하지 마라 — 016 §9.2-c 의 위험구조 논변이 기대는 것은 zero-init 쪽이다.**

> **⇒ 해상도는 이득의 크기를 정한다. 잔차 표현의 하방 봉쇄는 zero-init 에서 오지,
> 해상도 축에서 오지 않는다.**

### 4.6 ⚠ 정직하게 — 잔차 표현은 공짜가 아니다

같은 1/2 해상도에서 두 방식을 나란히 놓으면 잔차가 **진다.**

| 1/2 해상도에서 | DINO | Video | TOTAL | static 대비 |
|---|---:|---:|---:|---:|
| 정답 전체를 1/2 로 (`coarse:2`) | **0.03174** | **0.01305** | 0.50183 | **−0.05849** |
| static + 1/2 잔차 (`addblur2`) | 0.10271 | 0.00809 | 0.52234 | −0.03798 |

DINO 에서 3배 넘게 차이 난다(0.032 vs 0.103). 이유는 이렇다.

```
  정답을 1/2 로 뭉갠 것    : 전체가 흐리지만 **내용이 전부 맞다**
  static + 1/2 잔차        : 안 움직인 곳은 **선명하고 정확**하지만
                            움직인 곳은 **낡은 배경 위에 흐릿한 보정**이 얹힌 상태
```

DINOv2 는 "고르게 흐리지만 맞는 그림"을 "부분적으로 선명하지만 부분적으로 낡은 그림"보다
훨씬 좋아한다.

**그런데 이 비교로 설계를 정하면 안 된다.** 둘 다 오라클이라 **모델이 무엇을 배워야 하는지**를
전혀 반영하지 않기 때문이다.

```
  프레임 전체를 예측하는 모델 : 배경까지 **다시 그려야** 한다. 실패하면 쓰레기 영상
  잔차를 예측하는 모델        : 배경은 **그냥 흘려보낸다**. 실패하면 정확히 static
```

016 §9.2-c 가 잔차를 고른 이유가 성능이 아니라 위험 구조였다는 것을 다시 확인한다.
**이 표는 "잔차가 더 좋은 점수를 낸다"는 주장을 여전히 지지하지 않는다.**
지지하는 것은 **"잔차는 더 못해질 수가 없다"** 뿐이다.

> **설계서에서 다룰 것**: 잔차 표현의 이 DINO 손해(−0.02 어치)를 줄일 방법이 있는가.
> 후보 하나는 **잔차를 더할 때 배경 쪽도 살짝 함께 흐리는 것**(전역 일관성 확보)인데,
> 이건 §4.3 의 흐림 예산(σ ≤ 1.3px)과 정면으로 부딪힌다. 재 봐야 안다.

## 5. 측정 ③ — 평균내기 대리실험: 실패했다. 그러나 질문에는 답하지 못했다

### 5.1 왜 쟀나

017 §4 에서 찾은 것이다. 우리와 거의 같은 대회(1X World Model Challenge)의 우승팀이
확산모델을 버리지 않고 **샘플 20개를 픽셀공간에서 평균**내 PSNR +2.25dB 를 얻었다.

우리 1.1B 는 버릴 자산이 아니라 **평균 추정기로 재활용할 자산**일 수 있다.
다만 진짜 실험은 GPU 몇 시간이 든다. 그 전에 모델 없이 값싸게 물었다.

> **"그럴듯하지만 틀린 움직임" 여러 개를 평균내면 하나보다 나은가?**
> (표본 i 의 예측 = 첫프레임 + 행동이 비슷한 다른 표본 K개의 잔차 평균)

### 5.2 결과 — 오히려 나빠졌다

```
평균내기가 정말 이득인가 (Δ<0 이면 K개 평균이 낫다)
  avg2 vs avg1 @α=1     Δ=+0.00732  t=+1.57   45/96
  avg4 vs avg1 @α=1     Δ=+0.01558  t=+2.35   42/96
  avg8 vs avg1 @α=1     Δ=+0.01012  t=+1.53   38/96
  avg2 vs avg1 @α=0.5   Δ=+0.00493  t=+1.30   45/96
  avg4 vs avg1 @α=0.5   Δ=+0.00906  t=+1.71   37/96
  avg8 vs avg1 @α=0.5   Δ=−0.00157  t=−0.32   45/96
```

**단조 감소가 없다.** 사전 등록한 규칙(017 §8.4-D)에 따라
**"실제 K개 생성 실험의 우선순위를 낮춘다. 폐기는 아니다."**

### 5.3 왜 폐기가 아닌가 — 대리값이 질문에 안 맞는다

이 한계는 **측정 전에** 적어 뒀다(017 §8.3).

```
  남의 잔차 : **체계적으로** 틀리다(다른 방, 다른 물체).
              K개를 평균내면 K개의 다른 장면이 겹칠 뿐이고, 그건 더 틀린 것이다.

  확산 샘플 : 같은 조건에서 **무작위로** 흔들린다.
              평균이 조건부 평균으로 수렴한다. 이게 1X 우승팀이 얻은 것이다.
```

**구조가 다르다.** 그래서 이 실패로 실제 실험을 접을 수 없다.
**진짜 질문은 이것이다 — 우리 모델의 오차는 흔들림(분산)인가 치우침(편향)인가?**

```
  분산이면  →  샘플마다 다른 방향으로 틀린다.  평균이 고친다
  편향이면  →  일관되게 한 방향으로 틀린다.    평균은 아무것도 못 한다
```

**오늘 밤 이걸 잰다** (§9).

### 5.4 ⚠ 예비 신호 — 우리 모델의 오차는 **분산에 지배되는 것으로 보인다** (n=1, 확정 아님)

K샘플 채점 스크립트의 배선을 검증하다가 나온 값이다. 표본 하나뿐이므로 **결론이 아니다**
(016 §9.2 의 n=8 함정을 세 번 겪었다). 그래도 방향이 중요해 기록한다.

```
  sample_000000 에서 seed 0 과 seed 1 의 생성물을 비교하면

    샘플 간 흔들림  |seed0 − seed1|      평균 10.10   최대 183
    맞혀야 할 변화량 |정답 − 정지영상|    평균  7.88
    ─────────────────────────────────────────────────
    비율 = 1.28      **흔들림이 변화량보다 크다**
```

**읽는 법**: 같은 입력에 같은 모델인데 seed 만 바꿨더니, 두 결과의 차이가
**우리가 맞혀야 할 움직임보다 컸다.** 즉 모델이 "일관되게 틀린 방향으로 간다"기보다
**"매번 다른 방향으로 크게 흔들린다"** 는 뜻이다.

```
  오차가 분산이면  →  평균이 고친다.  K개 평균하면 분산이 약 1/K 로 준다
  오차가 편향이면  →  평균은 소용없다
```

**⇒ 1X WMC 우승 경로(017 §4)가 우리에게 이전될 전제조건이 충족되는 것으로 보인다.**
n=96 확정은 오늘 밤 체인이 낸다. 확정되면 **학습 없이, 이미 가진 체크포인트로**
제출 점수를 개선할 수 있다는 뜻이다.

부수로 확인한 것: 평균 영상을 mp4 로 쓰고 다시 읽는 왕복 오차가 **평균 1.43** 이다
(255 스케일 기준 0.6%). 학습 손실은 인코딩 전에 계산되는데 채점은 인코딩 후이므로,
이 틈이 점수에 얼마나 영향을 주는지도 오늘 밤 같이 나온다.

## 6. 부수 발견 넷

### 6.1 커널 기반 변환(CDNA/SepConv 계열)은 배제된다

017 §6.4 가 "커널 기반은 워핑과 덧셈 사이의 절충이고 로봇 조작을 위해 설계됐다"며
후보로 올렸다. 우리 데이터가 그것을 배제한다.

```
  누적 변위(프레임 0 대비, 레터박스와 t=0 을 빼고 잰 값)      (화면 폭이 512px 다)
      **표본별 값의 평균**   p95 24.0px   p99 59.9px   max 96.8px
      표본별 p99 의 중앙값   49.4px       전체 최댓값   233.5px
      ↑ 분포가 심하게 치우쳐 있어 평균과 중앙값이 다르다. 라벨을 정확히 적는다.

  커널 기반은 **커널 크기 ≥ 2 × 변위**가 필요하다
      중앙값 기준으로도 2×49.4 ≈ 99px,  평균 기준이면 120px
  SepConv 이 쓰는 커널이 51×51 이다. **어느 통계를 써도 자릿수가 다르다.**
```

※ 1라운드는 t=0 프레임(흐름이 정확히 0)과 레터박스 검은 띠를 포함해 백분위를 재서
**p99 를 55px 로 과소평가**했다(전체의 약 22% 가 0 이라 희석됐다). 검수 지적을 받아 고쳤다.

**한 프레임에서 16프레임을 한 번에 내는 구조에서는 커널 기반이 불가능하다.**
(프레임을 하나씩 이어붙이는 자기회귀라면 프레임당 변위가 1/15 로 줄어 이야기가 달라진다.
다만 그건 오차 누적을 부른다 — 017 §5.1⑦.)

### 6.2 libx264 는 완전한 정지영상조차 흔든다

`warp:0` 새너티를 만들다 발견했다. 정지영상 mp4 는 **프레임 0 을 16번 복사**해 만든 것인데,
디코드하면 프레임끼리 다르다.

```
  프레임 t 와 프레임 0 의 차이:  다른 픽셀 1.95%   최대 7단계   평균 0.026
  이 잡음만으로 생기는 DINO 거리: 최대 1.8e-04
```

크기(1e-4)는 우리가 재는 효과(1e-2)보다 **두 자릿수 작아서 어떤 결론도 위협하지 않는다.**

**그리고 2라운드에서 이 잡음의 부호까지 쟀다.**

```
  static (mp4 왕복, 16프레임)  −  staticexact (첫 프레임 16번 복사)
      DINO −0.00005   Video −0.00000   Action −0.00088   TOTAL −0.00037
```

**음수 = 인코딩 잡음이 있는 쪽이 오히려 근소하게 좋다.** 거의 전부 Action 에서 나온다
(−0.00088). 완전히 멈춘 영상보다 미세하게 떨리는 영상에서 action extractor 가
행동을 조금 더 잘 읽는 것으로 보인다.

> **⇒ "인코딩이 점수를 깎으니 무손실로 바꾸면 공짜 점수"라는 기대는 성립하지 않는다.**
> 적어도 **프레임 간 잡음** 축에서는 그렇다.
>
> 다만 이건 **절대 압축 손실이 아니다.** `staticexact` 도 디코드된 mp4 의 프레임 0 을
> 쓰므로 원본 PNG 대비 손실은 이미 안고 있다. 016 §8.1 이 잰 "정지영상 프레임 0 의
> DINO 오차 0.0036" 이 그 값이고, 그건 여전히 미측정 영역이다.
> 학습 손실은 인코딩 **전** 텐서로 계산되는데 채점은 인코딩 **후** 픽셀로 이뤄진다 —
> 이 틈은 **오늘 밤 K샘플 측정이 실제 생성물로 잰다**(017 §5.4).

### 6.3 홀드아웃이 학습 데이터와 겹친다 — 이제 코드로 확정했다

016 §11 이 구조적으로 지적했던 것을 정확히 확인했다.

**학습 데이터모듈의 분할 규칙** (`ldwma/datasets/lerobot_so100.py:270-285`):

```python
examples = 모든 데이터셋의 모든 에피소드 (길이 ≥ traj_len × downsample)
self.rng.shuffle(examples)                       # rng = random.Random(seed), seed 기본 0
val_count = int(len(examples) * val_fraction)    # val_fraction = 0.05
train split = examples[val_count:]               # 95%
val   split = examples[:val_count]               #  5%
```

**우리 홀드아웃 생성기** (`scripts/build_holdout.py` → `wm_eval/data_utils.iter_holdout_samples`):

```python
eps = list_episodes(train_root, ds, min_length=traj_len)   # ← 전체 에피소드. 배제 없음
```

**⇒ 홀드아웃 96개 중 약 95% 가 학습에 쓰인 에피소드다.**

지금은 무해하다 — 결론이 전부 "학습 데이터에서조차 진다"는 보수적 방향이기 때문이다.
**그러나 C 는 이기려고 만드는 것이다.** 이기는 순간 암기와 일반화를 구분할 수 없게 된다.
고치는 방법은 §8.3 에 확정해 뒀다.

### 6.4 우리 생성 설정은 이미 1X 의 권고를 따르고 있었다

017 §4 가 "CFG 를 켜면 거리 지표가 나빠진다(−0.68dB)"고 전했는데,
확인해 보니 `scripts/branchB/configs/eval/gen_1p1b.yaml` 이 이미
`unconditional_guidance_scale: 1.0`(=CFG 끔), `ddim_eta: 0.0`(결정론) 이다.

**즉 그 이득은 이미 우리 것이다.** 남은 것은 샘플 평균뿐이고, 샘플이 달라지는
유일한 원천은 **초기 노이즈**다.

## 7. 결론의 경계선 — 무엇을 말할 수 있고 무엇을 말할 수 없나

**말할 수 있는 것**

> 우리 채점기·우리 홀드아웃 96표본에서, **첫 프레임을 정답 유래 흐름으로 미는 것은
> 저역통과 덧셈 잔차보다 나은 표현이 아니다.** (사전 등록한 Gate 0·1 이 근거다.)
>
> ⚠ **왜 그런지는 아직 모른다.** 처음에는 "흐름 품질이 아니라 표현의 구조적 한계"라고
> 단정했으나 2차 검수에서 철회했다(§3.7③). 그림(§3.5)이 보여주는 것은
> **"팔이 안 지워진다"는 현상**이지 그 원인이 흐름 오차인지 드러남 미충전인지가 아니다.
> §9-c C(Farneback 대조)가 답한다.

**말할 수 없는 것**

- "워핑이 원리적으로 열등하다" — 아니다. 문헌은 `워핑 + 보정` 조합이 표준이라 말하고,
  우리 측정도 혼합이 순수 덧셈을 이긴다고 말한다(§3.8).
- "덧셈이 static 을 이길 것이다" — 오라클이 −0.0169 라는 뜻이지 **모델이 그걸 낸다는 뜻이 아니다.**
  우리 확산모델의 실력은 016 §9.2 기준 "남의 움직임 35% 세기"다.
- "eval 에서도 그럴 것이다" — 016 §5 가 로컬과 eval 이 **방향까지** 어긋난 전례를 남겼다.
- **모델이 잔차를 얼마나 잘 예측할지** — 이 측정이 답하지 못하는 가장 중요한 것이다.
  오라클 잔차는 정답에서 뽑은 것이다. 모델은 (첫프레임, 행동 16단계)만 보고 만들어야 한다.
  016 §9.2 기준 우리 확산모델의 실력은 "남의 움직임 35% 세기"이고, 그 지점은
  공정 바닥(§3.7②)에서 **손해 구간**이다. **잔차 노선이 성공한다는 근거는 아직 없다.**

**1차 검수의 우려 중 답한 것 / 못 답한 것**

| 우려 | 상태 |
|---|---|
| 뭉갬 배율 한 점에 걸린 결론 | ✅ **해소.** 네 배율 전부 같은 부호(TOTAL). k=8·16 무승부는 둘 다 죽은 지점이다 (§3.7①) |
| 새너티 미실행 | ✅ **해소.** `warp:0` 실질 통과 (§3.7④) |
| 바닥 비교의 편향 | ❌ **미해소.** 고친 것도 편향돼 있었다 (§3.7②) → §9-c B |
| "완벽한 흐름"이라는 전제 | ❌ **미해소.** 판정 기준을 사후에 갈아탔다 (§3.7③) → §9-c C |

**그리고 이건 오라클이다. 반증에는 쓰고 검증에는 쓰지 않는다.**

### 8.2 손실함수 — 채점 100% 를 직접 겨냥할 수 있다

017 §5 에서 확인한 것이다. **채점 3성분이 전부 미분 가능하고, 동결한 채 손실로 쓰는 것은
규정 위반이 아니다**(§4.1-4 는 *변경*만 금지한다).

```
  L = L_pixel(L1)  +  λ_d · L_DINO(1 − cos, CLS 384차원)  +  λ_a · L_action(MAE)
```

**반드시 지킬 것 셋** (전부 017 §5.3~5.5 의 근거가 있다):

1. **픽셀 손실을 버리면 안 된다.** 의미 잠재공간만으로 학습하면 행동 제어성이
   0으로 붕괴한 보고가 있다(Nano WM Finding #4: 성공률 25% → 0%).
2. **λ 는 값이 아니라 gradient norm 정렬로 잡는다.** 세 항의 gradient norm 과
   상호 코사인 유사도를 매 스텝 로깅한다. 음의 코사인이 지속되면 PCGrad 를 넣는다.
3. **홀드아웃에서 세 성분을 개별 추적한다.** 총점만 보면 "한 항이 오르고 두 항이 내리는"
   Goodhart 변곡점을 놓친다.

**값싼 최적화 둘** (둘 다 무손실):
- 정답 DINO CLS 를 **사전 계산해 캐시** → 정답 쪽 forward 가 0이 된다
- **프레임 서브샘플링 k=4** → DINO 성분이 프레임 평균이므로 균등 무작위 부분집합은
  전체 평균의 **불편 추정량**이다. 비용 정확히 1/4, 그래디언트 방향은 그대로

#### ⚠ 세 손실의 배선 사실 (코드로 확인, 2026-08-01 19:10)

| 항목 | DINO (30%) | R3D (30%) | **Action (40%)** |
|---|---|---|---|
| 시간축을 보나 | **아니다.** 프레임별 CLS | 그렇다 (3D conv) | **그렇다.** Conv3d + **양방향 GRU** |
| **프레임 서브샘플링** | ✅ 가능. 불편 추정량 | ❌ 불가 | ❌ **불가. 16프레임 전부 필요** |
| 크기 | ViT-S 22M (동결) | R3D-18 33M (동결) | **4.59M (동결)** |
| 입력 규격 | 518×518, 위아래 37.5% 검은 패딩 | 112×112 로 **찌그러뜨림**(종횡비 깨짐) | 320×512 그대로 |

**⇒ 서브샘플링으로 아낄 수 있는 것은 DINO 뿐이다.** 016·017 이 "프레임 서브샘플링 k=4 로
비용을 1/4 로" 라 적은 것은 **DINO 에만 해당한다.** R3D 와 Action 은 시간축 모델이라
프레임을 빼면 다른 것을 재게 된다.

다행히 **Action extractor 는 4.59M 으로 아주 작다.** 배점이 가장 큰 항(40%)을
가장 싼 비용으로 직접 겨냥할 수 있다는 뜻이다.

**⚠ 스케일 규약 함정**: `preprocess_images()` 는 **0~255 스케일**을 받아 `/255*2−1` 한다.
그런데 우리 데이터로더(`batch["video"]`)는 **이미 [−1,1]** 이다(§9-b).
손실에 넣기 전 **`(x+1)/2*255` 로 되돌려야 한다.** 안 그러면 조용히 잘못된 것을 최적화한다.

**배치 규격** (`lerobot_so100.py:383-407`, `feature_csv_utils.py:36-70` 확인):

```
  batch["video"]  (B, 3, 16, 320, 512)  float, 범위 [−1, 1]
                  ↑ 채점 공간과 **완전히 같은 전처리**다(리사이즈·레터박스 패딩 포함)
  batch["act"]    (B, 16, 6)            float, 정규화됨
  batch["caption"] / ["fps"] / ["frame_stride"] / ["start_idx"]
```

> **중요**: 학습 입력이 이미 채점 해상도(320×512)·채점 정규화([−1,1])와 일치한다.
> 별도 전처리를 만들 필요가 없고, §4.3 의 해상도 예산을 그대로 적용할 수 있다.

**확인한 것 — 구간 자르기의 무작위성 (2026-08-01 19:15, 결론: 실질 문제 없음)**

`__getitem__` 이 매번 `self.rng.randint(0, max_start)` 로 구간을 무작위로 자른다.
`self.rng` 는 `random.Random(seed)` 의 **사설 인스턴스**라 PyTorch 의 워커 시딩
(`worker.py:259` 의 `random.seed(...)` 는 **전역 모듈**만 건드린다)에 영향받지 않는다.
게다가 `DataLoader` 에 `persistent_workers` 가 없어 기본값 False 다.

처음에는 이것이 016 §3.2 의 암기 병리(같은 데이터를 같은 순서로 반복)와 같은 계열일까
의심했다. **확인해 보니 아니다. 두 이유로 상쇄된다.**

1. `shuffle=True` 라 에피소드 순서가 매 epoch 바뀐다. 구간 오프셋은 **호출 순서**에
   묶여 있으므로, 같은 에피소드가 매 epoch **다른 오프셋**과 짝지어진다.
2. `randint(0, max_start)` 가 소비하는 난수 비트 수는 `max_start` 에 따라 다르다.
   에피소드 길이가 제각각이라 워커별 수열이 곧 갈라진다.

**⇒ 확인 항목에서 지운다.** (다만 C 가 자체 데이터로더를 쓴다면 이 성질에 기대지 말고
명시적으로 워커별 시드를 주는 편이 안전하다.)

### 새로 써야 하는 것

branch B 는 DynamiCrafter 잠재확산 스택을 config 로 돌린 것이라
**C 는 config 변경이 아니라 새 모델 + 새 학습 루프**다.

```
  ① 모델        잔차 회귀기 (FiLM/AdaLN 행동 주입, 잔차 헤드 zero-init)
  ② 학습 루프    평범한 PyTorch 또는 Lightning
  ③ 손실        L1 + DINOv2 CLS 코사인 + action extractor MAE (017 §5, §8.2)

```

**규모 감각**: 문헌의 비슷한 시스템이 40M~176M 파라미터에 H200 1장 18시간이다

1.1B 를 쓴 것은 필요해서가 아니라 그 코드베이스에서 출발했기 때문이다.

## 10. 방법론 기록 — 오늘 배운 것

016 §4 의 목록에 셋을 더한다.

7. **임의로 고른 파라미터 하나에 결론이 걸리면 그 파라미터를 반드시 두 점 이상 게이트에 넣는다.**
   뭉갬 배율 k=4 만 걸었는데 k=8 에서 무승부가 나왔다(§3.6). 'seed 한 쌍'과 같은 실수다.
8. **SE 를 사전 추정할 때는 가장 큰 성분의 분산부터 센다.**
   Video 분산을 빼고 계산해 3.8배 빗나갔다(§2).
9. **게이트마다 유리/불리/무승부 세 경우를 전부 정의하고 진리표에 빈칸이 없는지 확인한다.**
   Gate 2 의 '불리'를 정의하지 않아 결과를 본 뒤에 정하게 될 뻔했다.
10. **"바닥"을 만들 때 두 팔이 지는 오차가 정말 같은 종류인지 확인한다.**
    `warpnbr`(내 픽셀을 틀린 방향으로)과 `addnbr`(다른 방의 델타를 통째로 이식)을
    같은 급으로 놓았다가 무효가 됐다. **그리고 고치면서 같은 실수를 반복했다** —
    새 바닥은 두 팔의 뭉갬 배율이 달랐다(§3.7②). **비교하려면 한 축만 달라야 한다.**
11. **새너티의 문턱은 값이 통과하는 자료형에 맞춘다.**
    float32 를 지나온 값에 1e-6 을 요구해 멀쩡한 검사가 '실패'로 찍혔다(§3.7④).
    픽셀 비교라면 **uint8 일치**로 걸어야 한다.
12. ⚠ **결과를 본 뒤에 설계한 측정은 "탐색적"이라고 라벨한다.**
    2라운드 전체가 1라운드 결과를 본 뒤에 설계됐는데, 문서 머리말은 여전히
    "판정선은 결과를 보기 전에 고정했다"고 적혀 있었다. **1라운드에만 참이었다.**
    확증과 탐색을 섞으면 사후 합리화를 사전 등록으로 착각한다.
13. ⚠ **판정 기준을 적어 놓고 결과를 본 뒤에 다른 지표로 갈아타지 않는다.**
    "t 에 비례하면 흐름 품질이 범인"이라 적어 놓고, 그대로면 불리한 답이 나오자
    픽셀 L1 로 갈아타 반대 결론을 냈다(§3.7③). **가장 부끄러운 실수다.**
14. ⚠ **오라클을 뭉갠 것과 모델이 그 해상도로 만든 것을 같다고 놓지 않는다.**
    전자는 저주파 **내용이 정답**이고 후자는 그것을 **창작해야 한다**.
    워핑을 죽일 때 쓴 잣대를 덧셈의 헤드룸에는 적용하지 않았다(§3.7⑤-b).
    **비판한 것과 같은 종류의 낙관을 반복하기 쉽다.**
15. ⚠ **같은 함수를 import 해서 같은 값이 나오는 것은 검증이 아니다.**
    §3.1 을 "독립 재현 검증"이라 불렀는데, 016 의 `blur_residual` 을 그대로 가져다 썼다.
    버그가 있었어도 100% 통과했을 것이다.

### 운영에서 데인 것 (내용이 아니라 배선 문제. 그래도 시간을 많이 먹었다)

1. **`set -euo pipefail` 아래에서 없는 디렉터리에 `ls`** — K샘플 체인이 배너만 찍고 즉사했다.
   `ls "$D"/*.mp4 2>/dev/null | wc -l` 은 디렉터리가 없으면 파이프라인 실패로 잡힌다.
   ⇒ `mkdir -p` 후 `find` 를 쓴다.
2. **셸 cwd 가 상위로 리셋되는 일이 있다** — 상대경로로 쓴 로그 리다이렉트가 조용히 실패해
   측정이 아예 안 돌았다. 오늘 세 번 겪었다.
   ⇒ **긴 작업의 스크립트·로그 경로는 절대경로로 쓴다.** tmux 로 띄울 때는
   `cd <repo> && ...` 를 명령 안에 넣는다.
3. **`pkill -f <패턴>` 이 자기 명령줄에 매치돼 셸을 죽였다.**
   ⇒ `pgrep -f "패턴[의마지막글자]" | xargs -r kill` 처럼 자기 자신을 피한다.
4. **f-string 안에 역슬래시를 못 넣는다**(py3.10). 표 헤더 `"α \ k"` 에서 터졌다.
   ⇒ 변수로 빼서 넣는다.
5. **긴 GPU 작업 앞에 짧은 스모크를 붙인다.** 3라운드 체인에 n=4 스모크 단계를 넣었다.
   33분을 태우고 나서 오타로 죽는 것을 막는다. ⚠ 단, **스모크 결과는 결론에 쓰지 않는다.**

그리고 오늘 값을 한 것:

- **판정선을 결과 전에 고정한 것.** 근거 ②가 틀렸다는 것이 사후에 드러났는데,
  미리 적어 뒀기 때문에 검증되고 정정될 수 있었다(§2). 그리고 **Gate 0 이 사전 등록대로
  발동한 덕분에**, 2라운드가 대부분 철회된 지금도 노선 결정은 확증 근거를 유지한다.
- **대리 실험의 한계를 측정 전에 적어 둔 것.** 평균내기 대리실험이 실패했을 때
  "그러므로 폐기"로 가지 않을 수 있었다(§5.3).
- **적대적 검수를 두 번 건 것.** 1차는 측정 설계를, 2차는 결론을 검수했다.
  2차가 치명 2건·중대 8건을 잡았고 **거의 전부 옳았다.**
  혼자였다면 §3.7②·③ 의 잘못된 결론이 그대로 C 설계서로 넘어갔을 것이다.
