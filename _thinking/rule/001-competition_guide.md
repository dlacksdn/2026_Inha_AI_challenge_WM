## 1. 대회 개요 (탭: 개요)

### 주제
현재 로봇 이미지와 Action Sequence를 바탕으로 **미래 로봇 영상을 생성하는 World Model 기반 AI 모델 개발**.

### 설명
- 월드 모델(World Model)은 현재 상태와 주어진 행동을 바탕으로 미래의 물리적 변화와 공간 관계를 예측하는 AI 모델이다.
- 참가자는 현재 로봇 이미지와 Action Sequence를 활용하여, 이후 로봇의 움직임과 환경 변화를 영상으로 생성하는 모델을 개발한다.
- 이미지와 행동 정보를 함께 이해하고 시공간적 변화를 예측하는 능력이 핵심이다.

### 주최/주관/운영
- 주최·주관: 인하대 인공지능융합연구센터, BK 산업융합형 차세대 인공지능 혁신인재 교육연구단, 인하대 앵커사업본부, 인하대 로봇특성화대학사업단
- 운영: 데이콘(DACON)

### 참가 대상
- 인공지능·로봇에 관심 있는 **인하대 학부생 및 대학원생** (팀당 2~5인)
- **휴학생 불가**: 대회 기간(7/16~8/20) 동안 전원 재학생이어야 함
- 팀원 중 **1인 이상은 9월에도 재학생** 신분이어야 함
  - 예) 팀원 4명이면 7/16~8/20 동안 4명 모두 재학생 + 그중 1명만 9월 중 재학생이면 됨
- 팀원 중 대학원생이 1명이라도 있으면 **대학원팀**으로 분류됨

## 3. 평가 방식 (탭: 평가)

### 3.1 리더보드 산식

```text
Score = 0.3 × DINO Component + 0.3 × Video Feature Component + 0.4 × Action Component
※ 0에 가까울수록 좋은 점수 (거리/오차 기반)
```

| 컴포넌트 | 가중치 | 무엇을 평가하나 | 계산 방식 |
|---|---|---|---|
| DINO Component | 0.3 | 프레임 단위 **시각적 특징**이 정답과 유사한가 | 제출킷이 추출한 feature ↔ 정답 feature 간 **Cosine Distance** |
| Video Feature Component | 0.3 | 영상 전체의 **시공간적 특징**이 정답과 유사한가 | 제출킷이 추출한 feature ↔ 정답 feature 간 **Cosine Distance** |
| Action Component | **0.4** | 생성 영상이 **주어진 행동 조건을 잘 반영**했는가 | 생성 영상에서 추정한 행동 ↔ 기준 행동 간 **MAE** |

- 모든 제출 파일은 반드시 공식 제출킷(`submission_kit`)으로 생성해야 하며, `make_submission_csv.py` 실행 결과를 수동 수정하거나 비공식 방식으로 생성하면 평가 대상에서 제외될 수 있다.
- 최종 수상 후보는 **제출 결과 재현 검증**을 거치며, 불일치 시 수상·점수가 취소될 수 있다.

### 3.2 Public / Private 분할
- **Public Score**: 전체 평가 데이터(eval) 중 사전 샘플링된 **30%**
- **Private Score**: 나머지 **70%**
- 최종 순위 = **정량 평가 100% (Private Score)**

### 3.3 수상 후보 코드 제출 (Private 리더보드 공개 후)
- 대회 종료(08.20 18:00) 후 공개되는 Private 리더보드 기준 **각 트랙별 상위 7팀(예비 2팀 포함)** 은
  **08.21(금) 14:00까지** `aix-server@inha.ac.kr` 메일로 소스코드 제출.
- 제출 코드는 **Private Score를 복원(재현)할 수 있어야** 한다.
- **컴퓨팅 제약 (재현 검증 기준)**:
  - 학습: train 데이터 대상, **최대 4일**, 단일 RTX PRO 6000 (VRAM 96GB)
  - 추론: eval 데이터 대상, **1시간 이내**, 단일 RTX PRO 6000 (VRAM 96GB)
- 코드 요건:
  - 데이터 입/출력 **상대 경로** 사용
  - 확장자 `.py` 또는 `.ipynb`, 인코딩 UTF-8
  - 모든 코드는 오류 없이 실행 (라이브러리 로딩 포함)
  - 개발 환경(OS)·라이브러리 버전 기재
- 제출 파일 목록:
  - Private Score 복원 가능한 **전처리·학습·추론 코드** (필수)
  - Private Score 복원 가능한 **모델 weight 파일** (필수)
  - **추론(Inference) 코드** (필수, 중요)

## 4. 규칙 (탭: 규칙 + 토크 공지 "대회 주요 규칙")

> 토크 공지 "대회 주요 규칙"(2026.07.15)은 규칙 탭의 1)~6)과 동일 내용을 재공지한 것이다.

### 4.1 대회 규칙 6조항

1. **사전학습모델 사용 가능 범위**
   - 공식적으로 **가중치가 공개**된 사전학습모델 중, 상업적/비상업적 이용이 허용된 라이선스만 사용 가능.
   - 예: MIT, Apache 2.0, CC BY, CC BY-NC 등
2. **API 사용 제한**
   - 원격 서버 API로만 접근 가능한 모델(OpenAI API, Gemini API 등) **사용 불가**.
   - 모든 모델은 **로컬 환경에서 직접 실행** 가능해야 함.
3. **외부 데이터 사용 불가**
   - 대회 제공 데이터만 사용 가능.
   - **eval 데이터는 어떤 형태로도 학습에 활용 금지.**
4. **Submission Kit 변경 금지**
   - submission_kit의 코드, 평가용 모델, checkpoint, 가중치를 **어떤 경우에도 변경 불가**.
   - 특히 `submission_kit/checkpoints/action_extractor.ckpt` **재학습·파라미터 변경 금지**.
   - 평가용 모델의 출력값이 달라지도록 수정하는 행위 = 규칙 위반.
5. **학습 및 추론 시간 제한**
   - 학습: RTX PRO 6000(96GB) 1대, 최대 4일
   - 추론: RTX PRO 6000(96GB) 1대, eval 전체 1시간 이내
6. **리더보드 제출용 CSV 생성 규칙**
   - CSV는 반드시 `submission_kit/make_submission_csv.py` 실행으로 생성.
   - 생성된 CSV의 **조작·보정·수정·후처리 일체 금지** (점수 향상 목적 값 변경 금지).
   - CSV 생성 과정은 베이스라인 코드 참고 권장.

### 4.2 유의사항

- **1일 최대 제출 횟수: 3회**
- 사용 가능 언어: **Python**
- 모든 CSV 데이터·제출 파일은 **UTF-8** 인코딩
- **Data Leakage 시 수상 제외**: 모델 학습에 eval 정보 활용 금지 (eval에 대한 Pseudo Labeling 포함)
- **최종 제출물 선택**: Private Score는 참가자가 제출 창에서 **직접 선택한 파일 1개**로 채점
  - 선택하지 않으면 Public Score 최고 제출물이 자동 선택됨
  - **선택 후 추가 제출하면 선택이 초기화**되어 다시 Public 최고 제출물로 자동 선택됨 (⚠️ 함정)
- 데이콘 부정 제출 이력이 있으면 평가 제한
- 대회 중 규칙 위반 의심 시 코드 제출 요청 가능 → **요청 2일 내 미제출 또는 외부 데이터 사용 확인 시 리더보드 기록 삭제**

## 7. 제출 절차 (배포 README + 토크 공지 종합)

```text
1) 모델 추론: eval 216개 샘플 각각에 대해 16프레임 mp4 생성
2) mp4를 submission_kit/input_videos/ 에 배치
   (sample_000000.mp4 ~ sample_000215.mp4 — 샘플 ID와 파일명 일치 필수)
3) cd submission_kit
   python -m pip install -r requirements.txt
   python make_submission_csv.py
4) 생성된 submission_features.csv 를 데이콘 '제출' 탭에 업로드 (1일 3회 한도)
5) 대회 종료 전, '제출' 탭에서 최종 채점 받을 파일 1개 선택 + 저장
```

- 제출 CSV 컬럼: `sample_id, feature_component, feature_json` (형식 예시는 `sample_submission.csv`)
- `input_videos/`에 mp4가 부족하면 제출킷이 누락 파일명을 알려줌
- 베이스라인(`baseline/baseline.ipynb`)은 선택 사항: 환경 설치 → backbone 다운로드 → 영상 생성 → CSV 생성까지 전 과정 예시 제공

### 12.2 Submission Kit 사용 목적 (원문)

> Submission Kit은 참가자가 추론을 통해 생성한 **최종 mp4 파일을 리더보드 제출용 CSV 파일로
> 변환하기 위해** 제공되는 공식 도구입니다.
>
> 따라서 Submission Kit은 **모든 영상 생성 및 추론이 완료된 이후, 제출 CSV를 생성하는
> 마지막 단계에서만 수정 없이 실행**해야 합니다.
>
> Submission Kit에 포함된 코드, 모델, checkpoint 및 기타 모든 구성요소는 **제출 파일 생성을 위한
> 목적으로만** 제공되며, **모델의 학습, 추론 또는 최종 결과물 생성 과정에 활용할 수 없습니다.**

### 12.3 사용이 제한되는 사례 — 5가지 (원문 그대로)

> 다음과 같이 Submission Kit의 구성요소 또는 실행 결과를 모델 성능에 영향을 주는 과정에
> 활용하는 것은 허용되지 않습니다.
>
> 1. Submission Kit에 포함된 **모델, 코드 또는 checkpoint를 활용하여 학습용 특징값이나 정보를
>    추출하는 행위**
> 2. **Test 데이터의 특징값을 추출하여 예측 결과를 선택하거나 보정하는 행위**
> 3. Submission Kit의 **실행 결과를 활용하여 최종 mp4 파일을 생성·선택·수정하는 행위**
> 4. Submission Kit 내부의 **모델·코드·정보를 학습, 추론, 후처리 또는 앙상블 과정에 활용하는 행위**
> 5. 그 밖에 Submission Kit을 **제출 CSV 생성 외의 목적으로 사용하여 모델 성능에 영향을 주는 행위**
>
> AI 모델의 학습과 추론, **후보 영상 생성 및 최종 영상 선택 과정은 Submission Kit 실행 이전에
> 모두 완료**되어야 합니다.

### 12.4 규정 위반 판단 기준 (원문)

> Submission Kit을 제출 CSV 생성 외의 목적으로 활용하고 이를 최종 결과 생성 또는 성능 개선에
> 반영한 경우, 기존 규정의 다음 조항에 해당할 수 있습니다.
>
> > **모델 학습에서 평가 데이터(eval) 정보 활용(Data Leakage) 시 수상 제외**
>
> 특히 **Test 데이터에서 추출한 정보를 활용하여 예측 결과를 보정하거나 선택하는 방식**은
> 평가 데이터 정보 활용으로 판단될 수 있으므로 유의해 주시기 바랍니다.

### 12.5 지켜야 할 실행 순서 (원문)

> 1. 참가자의 **학습 및 추론 코드만으로** 최종 mp4 파일 생성
> 2. 생성된 **최종 mp4 파일 확정**
> 3. 공식 Submission Kit을 **수정 없이 실행**
> 4. 리더보드 제출용 CSV 파일 생성 및 제출

### 12.6 소급 적용 범위 (원문)

> 그 **구조를 이용해 IDM 같은 모델을 만드는 것도 안 된다.**
> **제출용 CSV 를 만들 때에만** 사용되어야 한다.

013~018 이 만든 오라클 지도(흐림 예산·A-1/A-2 격자·잔차 해상도 표)는 **그대로 쓰되 갱신할 수 없다.**

### 13.4 ✅ 닫힌 질문 — 질의하지 않는다 (2026-08-08 확정)

"DINOv2·R3D 는 킷에 없는 공개 가중치이니 직접 받아 쓰면 되지 않나"를 한동안 회색으로 뒀다.
**그 해석을 폐기한다.**

> **규칙은 이것 하나다: 킷에 관련된 것은 전부 공개돼 있지 않은 것처럼 취급한다.**
> 어떤 모델을 쓰는지, 전처리가 어떤지, 산식이 어떤지 — **전부 모르는 것으로 놓는다.**
> 주최에 질의하지도 않는다.

**⇒ 따라서 아래는 전부 하지 않는다.**

```
❌ 킷이 쓰는 모델을 알아내 학습 손실에 넣기
❌ 킷의 전처리 규격을 재현해 자체 채점기 만들기
❌ 로컬에서 채점 점수를 흉내 내 체크포인트 고르기
❌ 위 항목들에 대한 주최 질의
```

**⇒ 우리가 하는 것.**

```
✅ 공개 문헌에서 고른 손실로 학습한다 (픽셀 L1, 주파수 손실, 자체 IDM 등)
   — 채점기를 겨냥해서가 아니라, 그 손실들이 문헌에서 좋은 영상 예측을 만들기 때문이다
✅ 판정은 리더보드로만 한다 (하루 10회)
✅ 킷은 최종 mp4 를 확정한 뒤 CSV 생성 시 1회만 실행한다
```

> **왜 이 해석을 택했나**: 017 §5.2 가 *"금지되는 것은 '변경'뿐이고 조문 그대로 읽으면
> 여지가 없다"* 며 회색지대를 확정으로 승격했다가 틀렸다(§12.7). 같은 실수를 반복하지 않는다.
> **규칙 해석에서 우리에게 유리한 쪽을 고르지 않는다.**

### 13.5 실무 처방

```
□ src/wm_eval/scoring.py 계열(run_m0·probe_*·measure_* 등 8개)은 실행 봉인
□ 최종 제출 코드 패키지에서 위 스크립트를 전부 배제한다 (한 줄이라도 남으면 평가 제외)
□ 자체 IDM 은 001 §2.1 의 킷 구조 기록을 보지 않고 외부 문헌만으로 설계한다
□ 킷은 최종 mp4 확정 후 CSV 생성 시 1회만 실행한다
```
