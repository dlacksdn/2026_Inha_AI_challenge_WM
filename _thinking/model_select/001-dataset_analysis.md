## 3. 폴더별 상세 분석

### 3.1 `data/train/` — 학습 데이터 (핵심)

**무엇이 들어있나**: Hugging Face **LeRobot 커뮤니티**에 공개된 SO-100 로봇 팔 조작
데이터셋을 55개 제공자(폴더명 = 업로더 계정명)로부터 모아 놓은 것. 각 데이터셋은
LeRobot v2.1 표준 포맷을 그대로 따른다.

**한 데이터셋의 내부 구조** (예: `aractingi/push_cube_offline_data`):

| 파일 | 내용 | 역할 |
|---|---|---|
| `meta/info.json` | fps, 해상도, 행동 차원·이름, 에피소드 수 등 스펙 | 데이터셋의 "명세서" |
| `meta/episodes.jsonl` | 에피소드별 `{길이, 작업 설명문}` | 예: `"Push the green cube to the yellow sticker"` |
| `data/chunk-000/episode_XXXXXX.parquet` | **프레임별 수치 데이터** (아래 표) | 행동·상태의 시계열 |
| `videos/chunk-000/observation.images.image/episode_XXXXXX.mp4` | 해당 에피소드의 카메라 영상 (AV1 코덱) | 시각 관측 |

**parquet 파일의 컬럼** (1행 = 영상의 1프레임과 1:1 대응):

| 컬럼 | 형태 | 의미 |
|---|---|---|
| `action` | float32 × 6 | 로봇에 **내린 명령** (목표 관절 각도) ← 모델의 조건 입력 |
| `observation.state` | float32 × 6 | 로봇의 **실제 관절 상태** (측정값) |
| `timestamp` | float32 | 에피소드 시작 기준 시각(초) |
| `frame_index`, `episode_index`, `index`, `task_index` | int64 | 각종 인덱스 |
| `next.reward`, `next.done` | int64 / bool | 강화학습용 필드 (본 대회에선 사실상 무시 가능) |

**행동(action) 6차원의 의미** — SO-100 로봇 팔의 관절 명령:

```text
[0] shoulder_pan   어깨 좌우 회전      [3] wrist_flex   손목 굽힘
[1] shoulder_lift  어깨 상하           [4] wrist_roll   손목 회전
[2] elbow_flex     팔꿈치 굽힘         [5] gripper      그리퍼 개폐
```
단위는 각도(도) 스케일의 원시값이며, 정규화되어 있지 않다.

**`so100_action_statistics.json`** — 행동값의 전역 mean/std (6차원).
학습 데이터 전체에서 계산된 정규화 상수로, **베이스라인 학습과 채점기(Action Component)가
모두 이 값으로 행동을 정규화**한다. 즉 참가자 모델도 이 상수를 쓰는 것이 안전하다.

**작업(task) 내용**: 큐브 집기/밀기, 물건을 상자에 넣기, 서랍 닫기, 테이프 집기,
체스 말 옮기기, 색깔별 분류 등 **탁상 위 물체 조작(tabletop manipulation)** 이 대부분이다.

**규모 상위 제공자** (프레임 수 기준):

| 제공자 | 데이터셋 | 에피소드 | 프레임 |
|---|---:|---:|---:|
| Chojins (체스) | 4 | 1,557 | 130,472 |
| dragon-95 | 3 | 481 | 72,281 |
| roboticshack | 9 | 649 | 65,203 |
| samsam0510 | 5 | 682 | 62,717 |
| sihyun77 | 8 | 303 | 42,950 |
| … (총 55명) | 128 | 11,132 | 1,025,666 |

### 3.2 `data/eval/` — 평가 입력 (216개 샘플)

| 폴더 | 파일 형식 | 내용 |
|---|---|---|
| `images/` | `sample_XXXXXX.png` (640×480 RGB) | 시나리오의 **시작 프레임 1장** |
| `actions/` | `sample_XXXXXX.npy` — 배열 (16, 6) float32 | 앞으로 수행할 **행동 16단계** (원시 단위, 비정규화) |

- 모델은 이 두 입력만으로 미래 16프레임을 생성해야 한다. **정답 영상은 제공되지 않는다**
  (서버가 숨겨진 정답 영상의 feature와 비교).
- 6fps 기준 16프레임 ≈ **2.67초**의 미래를 예측하는 셈이다.
- 규칙상 eval 데이터는 **학습에 어떤 형태로도 사용 금지** (pseudo-labeling 포함).

### 3.3 `submission_kit/` — 채점기의 절반이 손에 있다 (수정 금지)

생성한 mp4를 제출용 CSV로 바꾸는 도구이지만, 코드를 읽으면 **평가 산식의 실체**를 정확히 알 수 있다.

**처리 과정** (`make_submission_csv.py` → `feature_csv_utils.py`):

```text
mp4 (반드시 16프레임)
  → 320×512로 비율 유지 리사이즈 + 검은 패딩
  → 3가지 feature 추출 → CSV 기록
      ① Video Feature: R3D-18 (Kinetics-400 사전학습, 112×112 입력) → 512차원 벡터 1개
      ② DINO Feature : DINOv2 ViT-S/14 (timm) → 프레임당 384차원 × 16프레임
      ③ Action       : SO100ActionExtractor(3D CNN+BiGRU)로 영상에서 행동을 역추정
                        → 정답 행동(eval/actions, 정규화 후)과의 MAE "스칼라 1개"를 CSV에 기록
```

**분석에서 드러난 중요한 사실 3가지**:

1. **Action Component(가중치 40%)는 로컬에서 완전히 계산된다.**
   정답 행동(`eval/actions`)을 참가자가 이미 갖고 있으므로, CSV에 적히는 값 자체가
   최종 MAE 점수다. → **제출 전에 40%짜리 점수를 정확히 미리 알 수 있다.**
2. DINO·Video Feature는 CSV에 feature 벡터만 담기고, 서버가 숨겨진 정답 feature와
   **Cosine Distance**를 계산한다. → 이 부분만 서버 채점.
3. 채점용 모델 3개(R3D-18, DINOv2, action_extractor.ckpt)가 모두 공개되어 있으므로,
   학습 중 검증 지표를 채점 방식과 동일하게 구성할 수 있다
   (정답 영상이 있는 train 데이터로 로컬 모의채점 루프 구축 가능).

### 3.4 `baseline/` — 주최측 예시 모델

- **DynamiCrafter 계열 잠재 확산 모델**(`lvdm.models.ddpm3d.LatentVisualDiffusion`)에
  **행동 조건(action_conditioned=True, 6차원)** 을 추가한 구조. UNet 규모 약 11M 파라미터.
- 설정(`inha_action_diffusion_11M.yaml`): 입력 320×512 → 잠재공간 40×64,
  시퀀스 길이 16, 행동 정규화에 `so100_action_statistics.json` 사용, batch_size 1.
- `backbone.ckpt`(VAE·이미지 인코더 등)는 노트북 실행 시 자동 다운로드,
  학습된 `baseline_diffusion.ckpt` 제공 → **바로 영상 생성·제출까지 재현 가능**.
- 역할: (1) 전체 파이프라인의 동작 예시, (2) 점수 하한선, (3) 데이터 로더·전처리
  코드(`SO100DataModule`)의 참고 구현.

## 4. 대회 주최자가 데이터를 왜 이렇게 구성했는가? (요약)

1. **단일 로봇(SO-100)으로 통일** — 커뮤니티에서 모은 55명의 데이터임에도 로봇 기종,
   행동 6차원, 카메라 1대를 통일했다. 덕분에 "행동 공간이 같은 대규모 이종 환경
   데이터"가 되어, 참가자는 로봇별 행동 변환 없이 **순수하게 월드 모델(행동→미래 예측)
   학습**에 집중할 수 있다. 환경·배경·조명·태스크만 다양하므로 일반화 능력이 관건이 된다.

2. **eval에는 입력만 주고 정답 영상은 숨김** — 시작 이미지 + 행동 시퀀스라는 월드 모델의
   정의 그대로를 입력으로 주고, 출력(미래 영상)은 feature 비교로만 채점한다.
   정답 유출 없이 생성 품질을 정량 평가하기 위한 구조다.

3. **submission_kit으로 채점 절반을 참가자 로컬에 위임** — 영상 원본(216개 mp4) 대신
   feature CSV만 제출받아 서버 부담을 줄이고, 고정 checkpoint(수정 금지)로 채점의
   공정성·재현성을 보장한다. 부수 효과로 참가자는 채점 기준을 투명하게 알 수 있다.

4. **베이스라인 완제공(코드+가중치)** — 진입 장벽을 낮추고, "행동 조건부 영상 확산
   모델"이라는 출제 의도에 맞는 표준 접근법을 제시한다.

5. **정규화 상수(`so100_action_statistics.json`)를 train 폴더에 공식 배포** — 채점기와
   참가자 모델이 같은 스케일로 행동을 다루도록 기준을 하나로 고정했다.

## 5. 분석 중 발견한 주의사항 (함정 목록)

| # | 주의사항 | 상세 |
|---|---|---|
| 1 | **출력은 반드시 16프레임** | 채점기가 프레임 수를 검사하고 다르면 예외 발생. mp4의 fps 값 자체는 채점에 영향 없음(프레임만 디코딩). |
| 2 | **fps 예외 데이터셋 1개** | 128개 중 1개가 10fps. 시간 간격이 달라 학습 시 보정(스킵/제외) 판단 필요. |
| 3 | **해상도 예외 5개** | 720p 2개, 1080p 3개. 전처리(리사이즈+패딩)에서 통일 필요 — 채점기도 같은 방식(비율 유지+패딩) 사용. |
| 4 | **초단편 에피소드 존재** | 길이 최소 1프레임. 16프레임 미만 에피소드(전체의 0.3%)는 학습 샘플로 못 쓰므로 필터링 필요. |
| 5 | **action 통계의 count(974,661) ≠ 총 프레임(1,025,666)** | 통계가 일부 프레임 제외 후 계산된 것으로 추정. 직접 재계산하지 말고 **제공된 JSON을 그대로 쓸 것**(채점기가 이 값을 쓰므로). |
| 6 | **eval 행동은 비정규화 원시값** | 모델 입력 전 train 통계로 정규화하는 처리를 잊지 말 것 (베이스라인 `build_inference_batch` 참고). |
| 7 | **so100-blue/red 변형 3개** | 로봇 외형(색)만 다른 것으로 추정되나 시각적 도메인 차이가 될 수 있음. |
| 8 | **train 영상은 AV1 코덱** | 디코딩 환경(PyAV/ffmpeg의 AV1 지원) 사전 확인 필요. 원본 30fps를 5배 간격으로 뽑은 6fps라는 점도 시간 감각에 중요. |
| 9 | **submission_kit 일체 수정 금지** | 특히 `action_extractor.ckpt`. CSV 후처리·수기 수정도 규칙 위반. |

## 6. 다음 단계로 이어지는 시사점 (미리보기)

> 상세 학습 전략은 별도 문서에서 다루되, 데이터 분석에서 직접 도출되는 결론만 요약한다.

1. **로컬 모의채점 루프가 최우선 인프라** — 채점용 모델 3개가 전부 공개돼 있고
   Action(40%)은 아예 로컬 계산이므로, "생성 → feature 추출 → 점수 추정"을 자동화하면
   1일 3회 제출 제한과 무관하게 빠른 실험 반복이 가능하다.
2. **Action Component(40%) 공략이 곧 순위** — 생성 영상이 예뻐도 action_extractor가
   행동을 못 읽어내면 점수가 무너진다. 학습 중 이 extractor(고정)를 평가자로 활용해
   "행동이 읽히는 영상"을 만드는 방향으로 최적화해야 한다.
3. **데이터 품질 필터링 여지** — 128개 데이터셋의 품질·다양성 편차가 크다
   (최대 제공자 1명이 전체의 13%). 저품질/이상 에피소드 선별이 성능에 영향을 줄 수 있다.
4. **베이스라인(11M UNet)은 의도적으로 작다** — 96GB VRAM·학습 4일 제약 안에서
   모델 확장(더 큰 UNet, 더 좋은 사전학습 백본)의 여지가 크다.
