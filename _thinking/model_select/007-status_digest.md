## 1. 한 장 요약 — 지금 어디에 있나

```
[과제]  로봇 사진 1장 + 앞으로 할 행동 16단계  →  미래 영상 16프레임 생성
[채점]  Score = 0.3×DINO + 0.3×Video + 0.4×Action   (0에 가까울수록 좋음)

[여기까지 확정된 3가지]
 ① 넘어야 할 상대는 주최 baseline이 아니라 "아무것도 안 하기"다.
      static(첫 프레임 16번 복사) 0.560  <  baseline 11M 0.711   ← baseline이 더 나쁘다
      (정답 영상 자체 = 0.489 이 이론상 하한)
 ② Action(40%)은 손댈 수 없는 상수다 (~1.2).
      원인: 채점용 추출기가 단안 영상에서 shoulder_lift·elbow_flex(깊이 방향 관절)를 못 읽는다.
      정답 영상을 넣어도 1.223 → 생성 품질로 개선 불가.
 ③ 승부처는 60%(DINO+Video)의 "정확한 작은 움직임"이다.
      실제 미래는 거의 정지(모션 4.81)인데 11M은 그 1.8배로 과하게 움직인다(= 드리프트).

[검증되어 지워진 두 가지 가설]
 ✗ "액션 CFG(λ)로 점수를 얻는다"  → λ를 올릴수록 단조 악화. 폐기 (M3 Part A)
 ✗ "1.1B는 추론 1시간을 못 지킨다" → 실측 결과 넉넉히 들어감. 예산은 병목 아님 (M1)

[지금 상태]
 - 남은 큰 질문: "생성 모델이 static 0.560을 넘을 수 있는가?" — 아직 아무도 못 넘었다.
 - 다음 갈래: (A) 1.1B 승격으로 드리프트를 줄이나  (B) anti-drift 설계로 직접 겨냥
 - 막힌 것: M3 Part B(11M 재학습)가 5090 드라이버 문제로 미완 + 5090 당분간 사용 불가
 - 그래서 이 문서 이후의 초점: **8GB 집 컴퓨터에서 할 수 있는 것으로 재배치** (§7)
```

## 2. 과제 구조 — 무엇이 들어가고 무엇이 채점되나

```
                          [ 입력 ]                                  [ 우리가 만드는 것 ]
   eval/images/sample_XXXXXX.png   (시작 사진 1장, 640×480)
   eval/actions/sample_XXXXXX.npy  (앞으로의 행동 16스텝 × 6축)   →   sample_XXXXXX.mp4
                                                                      (정확히 16프레임)
                                                                      × 216개 전부

                          [ 채점 : submission_kit (수정 금지) ]
   우리 mp4 ─┬─ R3D-18 (112×112로 축소)      → 512차원 벡터 1개   ─┐
             ├─ DINOv2 (프레임별, 518×518)   → (16, 384) CLS      ─┼→ 정답 feature와 코사인 거리
             └─ action_extractor (고정 ckpt)  → (16,6) 관절각 예측  ─┘   (Action은 정답과 MAE)

   Score = 0.3 × DINO거리 + 0.3 × Video거리 + 0.4 × ActionMAE      ← 0에 가까울수록 좋음
```

핵심 구조적 사실 3가지:

| 사실 | 왜 중요한가 |
|---|---|
| **Action(40%)은 로컬에서 완전히 계산된다** | 정답 행동(actions/*.npy)을 우리가 갖고 있어서, 제출 전에 40%짜리 점수를 정확히 안다 |
| **DINO·Video는 정답 영상 feature와 비교** → 서버만 계산 | 우리는 train 홀드아웃으로 "모의 채점"을 만들어 대신 쓴다(§3-D 홀드아웃) |
| **세 지표 전부 저해상·전역 정보만 본다** | R3D는 112×112로 축소, DINO는 CLS 토큰 1개, Action은 공간 전역 평균 풀링 → **고화질 텍스처는 채점에 거의 반영 안 됨** |

## 3. 용어 사전

### 3-A. 대회 / 과제 용어

| 용어 | 뜻 | 이 프로젝트에서의 값 |
|---|---|---|
| **World Model (월드 모델)** | 현재 상태 + 행동 → 미래를 예측하는 모델 | 사진+행동 → 미래 영상 |
| **action-conditioned** | 행동(action)을 조건으로 받아 생성 | 프레임마다 6차원 행동을 넣는다 |
| **SO-100** | 학습 데이터에 쓰인 저가 로봇 팔 (단일 기종) | 6축: `shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper` |
| **LeRobot 포맷** | HuggingFace 로봇 데이터 표준 (영상 mp4 + 수치 parquet + meta) | train 128개 데이터셋, 11,132 에피소드, 102만 프레임 |
| **에피소드(episode)** | 로봇이 작업을 한 번 시연한 기록 | 중앙값 80프레임, 6fps |
| **eval / train** | eval=제출용 입력(정답 없음, 216개), train=학습용(정답 영상 있음) | **eval을 학습에 쓰면 실격** |
| **submission_kit** | 주최측 채점 도구 (feature 추출 + CSV 생성) | **일절 수정 금지.** 우리는 import만 해서 재사용 |
| **baseline (주최)** | 주최가 준 예시 모델 = 11M UNet 확산모델 + 학습된 가중치 | 성능 하한 참고용. **M0에서 static보다 나쁨이 밝혀짐** |
| **Public / Private** | 리더보드 점수 분할 (30% / 70%) | 최종 순위 = Private 100% |

### 3-B. 확산 모델(diffusion) 용어 — 우리가 쓰는 모델의 작동 원리

```
[잠재 확산 모델(Latent Diffusion)의 그림]

  사진/영상 ──VAE 인코더──> 잠재(latent, 작게 압축된 표현) ──> [ UNet이 노이즈를 제거 ] ──VAE 디코더──> 영상
                                 320×512 → 40×64                  이 과정을 N스텝 반복
```

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **VAE** | 영상↔잠재 변환기(압축/복원). 확산은 잠재공간에서 일어난다 | 320×512 → 잠재 40×64. backbone.ckpt에 들어있음 |
| **잠재(latent)** | 영상을 작게 압축한 표현. 계산량을 줄이는 장치 | 채널 4, 40×64, 16프레임 |
| **UNet** | 노이즈를 제거하는 본체 신경망. **여기가 "모델 크기"의 주체** | 11M(주최) vs 1.46B(DynamiCrafter 규격) |
| **DDIM step (스텝)** | 노이즈를 몇 번에 걸쳐 걷어내는가. 많으면 품질↑ 시간↑ | 주최 기본 50스텝 |
| **NFE** | *Number of Function Evaluations* = UNet을 실제로 몇 번 부르는가 = **스텝 × (CFG 켜면 2, 끄면 1)** | 시간 예산의 단위. 50스텝+CFG = NFE 100 |
| **CFG (classifier-free guidance)** | 조건을 준 예측과 안 준 예측의 차이를 λ배 증폭해 "조건을 더 강하게" 반영 `ε = ε_cond + λ(ε_cond − ε_uncond)` | **M3 Part A에서 폐기 판정.** λ↑ = 점수 악화 |
| **λ (lambda)** | CFG 강도. λ=1.0이면 CFG 꺼짐 | 스윕 결과 λ=1.0이 최선(=끄는 게 최선) |
| **uncond 분기** | CFG에서 "조건 없이" 예측하는 쪽 | 현 코드는 액션뿐 아니라 텍스트·이미지도 함께 비움 → 순수 액션 CFG가 아니다 |
| **action_dropout_prob** | 학습 중 액션을 확률적으로 지워서 uncond 분기를 학습시키는 설정 | 주최 baseline은 0.0(꺼짐). Part B는 0.1로 켜서 재학습 시도 |
| **guidance_rescale** | 고-λ에서 분산이 과증폭되는 것을 되당기는 보정 | 0.7 고정 (즉 CFG 악화 결론은 보수적) |
| **EMA** | 학습 중 가중치의 이동평균 사본. 추론 시 보통 이걸 쓴다 | 로그의 "Switched to EMA weights" |
| **warm-start** | 이미 학습된 가중치를 불러와 이어 학습 | Part B: 학습된 11M UNet을 얹고 dropout만 켜서 계속 학습 |
| **파인튜닝 / LoRA** | 전체 재학습 대신 일부만/저차원 어댑터만 학습해 비용 절감 | 1.1B를 4일 예산에 넣을 때의 수단 |
| **DynamiCrafter (DC)** | 이미지→영상 확산 모델(공개 가중치). 주최 baseline의 계보 | `backbone.ckpt`(~10GB)가 이것. 320×512·16프레임 규격이 대회와 일치 |
| **backbone.ckpt** | VAE+CLIP 등 "몸통" 가중치 파일 | 주최 노트북이 HF에서 직접 다운로드 → 라이선스 문제 없음 |
| **temporal (시간축) 레이어** | 프레임 간 관계를 처리하는 층(3D UNet) | **DC 원본 UNet엔 이 키가 없어** 1.1B 가중치를 그대로 못 얹는다(=열린 문제) |

### 3-C. 채점 관련 용어

| 용어 | 뜻 | 세부 |
|---|---|---|
| **DINOv2 / CLS 토큰** | 자기지도학습 비전 모델. CLS 토큰은 이미지 전체의 "의미 요약" 벡터 | ViT-S/14, 프레임당 384차원. 세밀한 픽셀이 아니라 "무슨 장면인지"를 봄 |
| **R3D-18** | 3D CNN 영상 분류 모델(Kinetics 사전학습). 시공간 패턴을 요약 | 입력을 **112×112로 축소** → 512차원 1개 |
| **코사인 거리** | 두 벡터의 방향 차이. `1 − cos유사도`. 같으면 0 | DINO·Video가 이걸 쓴다 (서버 집계 방식은 §6 미확인 항목) |
| **MAE** | 평균 절대 오차 | Action = 예측 관절각 vs 정답의 MAE (정규화 공간) |
| **정규화(z-score)** | `(값 − 평균) / 표준편차`로 스케일 통일 | `so100_action_statistics.json`의 mean/std 사용(채점기와 동일) |
| **action_extractor** | 영상에서 관절각을 역추정하는 고정 모델(채점용) | 3D CNN → **공간 전역 평균 풀링** → BiGRU → 프레임별 6D. 재학습 금지 |

### 3-D. 우리 프로젝트 고유 용어 (여기부터가 진행 이해의 핵심)

| 용어 | 뜻 | 값/의미 |
|---|---|---|
| **홀드아웃(holdout)** | train에서 잘라낸 자체 평가셋. eval 대신 쓰는 "모의고사" | 96표본(96개 데이터셋에서 1~2개씩, seed=0). 구성: 시작이미지+16액션+정답16프레임 |
| **모의채점(local scoring)** | submission_kit 코드를 재사용해 로컬에서 0.3/0.3/0.4를 계산 | `scripts/run_m0.py`. 제출 3회/일 제한과 무관하게 무한 실험 가능 |
| **static** | 시작 프레임을 16번 복사한 "정지 영상" 예측기 | **TOTAL 0.56032 — 현재 넘어야 할 기준선** |
| **GT upper bound** | 정답 영상 자체를 채점한 값 = 이론상 하한 | TOTAL 0.48911 (DINO·Video는 0, Action만 1.223 남음) |
| **TOTAL** | 우리가 재현한 대회 산식 최종 점수 | 0.3·DINO + 0.3·Video + 0.4·Action |
| **motion (모션)** | 프레임 간 평균 픽셀 변화량 = "얼마나 움직이나"의 대용 지표 | GT 4.81 / baseline(λ=1) 8.81 / λ=4.0 11.45 |
| **드리프트(drift)** | 생성이 진행될수록 정답에서 멀어지는 현상 | 프레임0 DINO 0.03~0.20 → 후반 0.6~0.7로 상승 |
| **환각(hallucination)** | 실제로 없는 움직임·물체를 만들어내는 것 | 11M이 정지 장면에 과한 움직임을 넣는 것 |
| **anti-drift** | 드리프트를 억제하는 설계(첫 프레임 앵커링·저모션 정규화 등) | 아직 미실험. 다음 갈래 (B) |
| **branch A / branch B** | 백본 크기 분기. A=중형 스크래치(100~400M), B=DC 1.1B 승격 | 004에서 "측정 후 결정"으로 미뤄둔 것 |
| **게이트 G1/G2/G3** | 새 머신 환경 검증 3단계 | G1 CUDA+채점모델 / G2 홀드아웃 재현 / G3 static·GT 수치 일치 |
| **M0~M4** | 작업 단계 이름 | M0 바닥값, M1 추론예산, M2 분기결정, M3 CFG·재학습 파일럿, M4 본학습 |
| **r (배율)** | 최종 장비 RTX PRO 6000이 A100보다 몇 배 빠른가 | 실측 추정 **2.08~2.70×** (004의 보수 가정 0.8~1.3보다 유리) |
| **in-distribution 이점** | 평가 데이터가 모델이 학습한 분포 안에 있어 유리한 상황 | baseline은 train에 학습됐고 홀드아웃도 train → **baseline에 유리한데도 static에 졌다**(결론이 보수적) |

## 4. 진행 타임라인 — 무엇을 왜 했나

```
001 대회 가이드      규칙·일정·제약 정리 (학습4일/추론1h/eval금지/kit수정금지)
001 데이터 분석      train 실측: 128셋·11,132에피소드·6fps·6축·640×480
        │
002 모델 선정 1차    "Vid2World 1순위" 결론 (DC 백본 규격 일치 + 액션 CFG 레시피)
        │
003 적대적 검수      critic이 002를 공격: ① 지표가 저해상이라 대형백본 근거 없음
        │             ② 추론 1시간 이미 초과 ③ 액션 드롭아웃은 baseline에 이미 있음
        │
004 최종 선정 v2     제3자 심판. "Vid2World 채택" 프레이밍 폐기.
        │             → DC 계열 유지 + CFG 활성화 + 백본 크기는 "측정 후 분기"
        │             → critic의 GPU 배율(0.4~0.8×)은 FP32 수치 오독으로 반박
        │             → 규율 확립: "M0·M1 측정 없이 학습 시작 금지"
        │
[집 4060 Ti] M0     모의채점 인프라 구축 + 바닥값 측정  ★ 판을 뒤집은 결과
        │             static 0.560 < baseline 0.711  (baseline이 더 나쁨, 100% 표본)
        │             Action 40%는 상수 확정 / 승부처는 60%
        │
[5090] 005 = M1     1.1B 추론 예산 실측 + 환경 재현 검증
        │             예산 여유 확인 → "추론 1시간" 리스크 해소. r ≈ 2.1~2.7×
        │
[5090] 006 = M3     Part A: λ-CFG 스윕 → 단조 악화, CFG 폐기 (결정적 음성)
        │             Part B: 11M 재학습 → 드라이버 불일치로 미완 (코드는 준비 완료)
        │
007 (이 문서)        여기까지 종합 + 5090 없는 상황에서의 재배치
```

각 단계의 "왜"를 한 줄로:

| 단계 | 왜 했나 | 무엇을 얻었나 |
|---|---|---|
| 002→003→004 | 어떤 모델로 갈지 결정하려고 | 서사 대신 **측정으로 결정하기로** 규율을 세움 |
| M0 | "큰 백본이 정말 이득인가"를 재기 전에 바닥값이 필요해서 | 기준선이 baseline이 아니라 **static**임을 발견 |
| M1 | 1.1B가 예산 안에 드는지 몰라서(집에선 못 잼) | 예산 병목 **해소** |
| M3-A | CFG가 값싼 점수 레버라는 가설 검증 | 가설 **반증**(단조 악화) |

## 5. 측정된 숫자 총괄표 (전부 홀드아웃 96표본, 0에 가까울수록 좋음)

### 5.1 예측기별 점수 — 이 표가 전체의 핵심

| 예측기 | DINO(30%) | Video(30%) | Action(40%) | **TOTAL** | 해석 |
|---|---:|---:|---:|---:|---|
| **GT (정답 영상)** | 0.00000 | 0.00000 | 1.22278 | **0.48911** | 이론상 하한. Action이 안 0인 게 추출기 한계 |
| **static (정지)** | 0.12304 | 0.09113 | 1.24017 | **0.56032** | ★ 넘어야 할 기준 |
| baseline 11M (λ=1.0) | 0.54968 | 0.21534 | 1.19163 | 0.70616 | 5090 실측 |
| baseline 11M (집 M0) | 0.55558 | 0.22196 | 1.19509 | 0.71130 | 집 4060 Ti 실측(위와 일치) |
| baseline + CFG λ=1.5 | 0.55740 | 0.22031 | 1.19324 | 0.71061 | ↓ 이하 단조 악화 |
| baseline + CFG λ=2.0 | 0.56364 | 0.22521 | 1.19285 | 0.71379 | |
| baseline + CFG λ=2.5 | 0.57144 | 0.23078 | 1.19648 | 0.71926 | |
| baseline + CFG λ=3.0 | 0.57973 | 0.23600 | 1.19436 | 0.72247 | |
| baseline + CFG λ=4.0 | 0.59587 | 0.24831 | 1.19430 | 0.73098 | 최악 |

읽는 법:
- **static의 DINO 0.123 / Video 0.091**이 우리가 깨야 하는 벽이다. baseline은 DINO에서 4.5배, Video에서 2.4배 나쁘다.
- Action은 어느 줄에서도 1.19~1.24 — **아무리 해도 안 움직인다**(40%가 사실상 고정 감점).
- 개선 가능한 총 폭: static 0.560 → GT 0.489 = **0.071**. 그중 DINO+Video가 0.064, Action이 0.007.

### 5.2 Action 차원별 MAE — 왜 Action이 상수인가

| 예측기 | pan | **lift** | **elbow** | wflex | wroll | grip |
|---|---:|---:|---:|---:|---:|---:|
| static | 1.16 | **1.84** | **1.72** | 0.78 | 0.97 | 0.97 |
| baseline | 1.09 | **1.90** | **1.52** | 0.75 | 0.99 | 0.92 |
| GT | 1.12 | **1.85** | **1.68** | 0.76 | 0.98 | 0.94 |

- `shoulder_lift`·`elbow_flex`가 오차를 지배한다. 이 둘은 **카메라 깊이 방향** 관절이라 단안 영상에서 각도 복원이 원리적으로 어렵다.
- **정답 영상(GT)조차 1.85 / 1.68** → 추출기 자체의 한계. 우리가 어떤 영상을 만들어도 못 내린다.

### 5.3 모션 분석 — CFG가 왜 나쁜가

| | GT | λ=1.0 | λ=1.5 | λ=2.0 | λ=2.5 | λ=3.0 | λ=4.0 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 프레임간 평균 |Δpixel| | 4.81 | 8.81 | 9.15 | 9.54 | 9.99 | 10.46 | 11.45 |
| GT 대비 | 1.0× | 1.8× | 1.9× | 2.0× | 2.1× | 2.2× | **2.4×** |

- `corr(λ, motion) = +0.997` — λ를 올리면 움직임이 거의 완벽히 단조 증가.
- **실제 미래는 거의 정지(4.81)인데 11M은 이미 1.8배 과하게 움직이고, CFG는 그걸 더 키운다.** 그래서 점수가 나빠진다.

### 5.4 M1 추론 예산 (1.1B UNet = 1462.6M, RTX 5090 실측)

| 스텝 | CFG | NFE | sec/샘플 | peak VRAM | 216샘플(분) | 6000 추정(분) | 예산 60분 |
|---:|:--:|---:|---:|---:|---:|---:|:--:|
| 10 | off | 10 | 2.73 | 17.1G | 9.8 | ~9 | ✅ |
| 16 | off | 16 | 3.80 | 17.1G | 13.7 | ~12 | ✅ |
| 25 | off | 25 | 5.39 | 17.1G | 19.4 | ~17 | ✅ |
| 50 | off | 50 | 9.78 | 17.1G | 35.2 | 29~32 | ✅ |
| 16 | **on** | 32 | 6.64 | 17.1G | 23.9 | 20~22 | ✅ |
| 25 | **on** | 50 | 9.84 | 17.1G | 35.4 | 30~32 | ✅ |
| **50** | **on** | **100** | 18.73 | 17.1G | **67.4** | 56~61 | ⚠️ 경계 |

- 시간 공식: **sec/샘플 = 0.1776 × NFE + 0.949** (뒤 항은 VAE·CLIP 고정비)
- **배치를 키워도 빨라지지 않는다**(batch 1 vs 2 동일) → 004의 "배칭으로 예산 확보" 주장 반증 확증

## 10. 한 문단 결론

지금까지 우리가 한 일의 본질은 **"측정으로 가설을 죽이는 것"**이었다. 002가 서사로 세운 "큰 백본 + 액션 CFG" 계획은
003의 검수와 004의 심판을 거쳐 "측정 후 결정"으로 유보됐고, 이후 세 번의 실측이 그 계획의 절반을 실제로 지웠다:
**CFG는 점수를 깎고**(M3-A), **Action 40%는 손댈 수 없으며**(M0), **추론 예산은 걱정거리가 아니었다**(M1).
동시에 M0는 판을 바꾸는 사실을 하나 세웠다 — **주최 baseline보다 "아무것도 안 하기"가 낫다.**
그래서 남은 문제는 명확하다: *거의 정지한 미래를, 정지보다 조금 더 정확하게 그려낼 수 있는가.*
그 답을 얻는 열쇠는 모델을 키우는 것 자체가 아니라 **드리프트를 잡는 것**이고, 다음 실험의 1차 성공 신호는
TOTAL 점수보다 **모션이 GT(4.81)에 접근하는지**다. 5090이 닫힌 지금은, 그 가설을 8GB에서 값싸게
시험할 수 있는 무학습 실험(§7.2 가)이 가장 정보량이 큰 다음 행동이다.
