## 3. 실행 순서 (그대로 따라간다)

각 명령은 저장소 루트에서 실행한다. 학습·생성 로그는 반드시 `tee` 로 `run_logs/` 에 남긴다.

### 단계 0 — 환경 게이트 + 홀드아웃 재생성 (10~20분)

`artifacts/` 는 gitignore 라 이 머신엔 홀드아웃이 없다. 먼저 만든다.

```bash
conda run -n wm python scripts/branchB/preflight.py
```
**기대**: 마지막 줄 `판정: PASS`, 그리고 `추천 scope=action_temporal`.
**실패 시**:
- `GPU 커널 실행 FAIL` → **006 이 막혔던 바로 그 지점**이다. cu128 재설치(§2.3) 후 다시.
- `pkg numpy` FAIL(2.x) → `pip install numpy==1.26.4`.
- `pkg_resources` FAIL → `pip install "setuptools<70"`.

```bash
conda run -n wm python scripts/build_holdout.py --train-root open/data/train \
    --out artifacts/holdout --n 96 --seed 0 --per-dataset-cap 2
conda run -n wm python scripts/branchB/make_smoke_holdout.py     # → artifacts/holdout_smoke4
conda run -n wm python scripts/run_m0.py --holdout artifacts/holdout --out artifacts/m0 \
    2>&1 | tee run_logs/5090_m0_$(date +%m%d_%H%M).log
```
**기대(집과 소수 3자리까지 일치해야 한다)**: `static` TOTAL ≈ **0.560** / DINO ≈ **0.123** / Video ≈ 0.091,
`gt_upper_bound` DINO·Video = **0.000**.
**어긋나면** 데이터·환경 불일치다. 그 상태로 학습하지 마라 — 원인부터 규명하라.

BRANCHB_TRAIN_SCOPE=action_temporal BRANCHB_BUILD_ONLY=1 \
  bash scripts/branchB/run_1p1b_train.sh 2>&1 | tee run_logs/5090_buildonly_$(date +%m%d_%H%M).log

**기대 출력(하나라도 다르면 멈추고 원인 규명)**

### 단계 2 — S4 스모크 학습 20스텝 (10~20분)

```bash
BRANCHB_TRAIN_SCOPE=action_temporal \
  bash scripts/branchB/run_1p1b_train.sh 20 "00:00:40:00" \
  2>&1 | tee run_logs/5090_1p1b_smoke_$(date +%m%d_%H%M).log
```
**기대**: loss 가 찍히고, `max_steps=20 reached` 로 정상 종료되고, 체크포인트가 생긴다.
**기록할 숫자(보고 필수)**: ① `s/it` ② peak VRAM(`nvidia-smi` 병행) ③ loss 초기값·20스텝 후 ④ 체크포인트 크기
```bash
du -h artifacts/branchB/train_out/inha_action_diffusion_1p1b/checkpoints/* | sort -k2
```
**예상**: 체크포인트 1개 ≈ **10.7GiB**(UNet+EMA). 이 값으로 **영구 아카이브 주기**를 정한다
(현재 5000스텝, `lightning.callbacks.metrics_over_trainsteps_checkpoint.params.every_n_train_steps=<N>` 로 조정).
디스크 여유를 먼저 확인하라: `df -h .`

### 단계 3 — 액션 민감도 기준값 (5분, CPU 가능)

학습 전(0초기화 직후)에는 **정확히 0** 이 나와야 정상이다. 이 값을 기준으로 학습 후와 비교한다.

```bash
conda run -n wm python scripts/branchB/probe_action_sensitivity.py --device cuda --n-pairs 3
conda run -n wm python scripts/branchB/probe_action_sensitivity.py --device cuda --n-pairs 3 \
    --ckpt artifacts/branchB/train_out/inha_action_diffusion_1p1b/checkpoints/last.ckpt
```
**집에서 이미 측정한 기준값**(`results/branchB/action_sensitivity_init.json`, 홀드아웃 실제 액션 3개 사용):
```
act0 vs act1  상대차 0.000000     act0 vs null  상대차 0.000000
act1 vs act2  상대차 0.000000     → 평균 S_AB = S_A0 = 0.000000  (0초기화가 의도대로 작동)
```
**의미**: 학습본에서 `mean_S_AB` 가 0 에서 벗어나기 시작하면 액션이 개입하는 것이다.
20스텝은 너무 짧아 여전히 0 에 가까울 수 있다 — **단계 5(파일럿 후)에 다시 재는 것이 본 검사다.**

## 4. 판정 기준 (단계 5 의 DINO 로만)

| 파일럿 DINO | 해석 | 다음 행동 |
|---|---|---|
| **< 0.123** | **처음으로 생성이 정지를 이겼다** | 즉시 본 학습 준비(6000, scope=full). 사용자에게 보고 |
| 0.123 ~ 0.30 | 방향은 맞다(11M 재학습 0.481 보다 크게 좋음) | 학습을 더 돌려 추세 확인 → 본 학습 |
| 0.30 ~ 0.48 | 사전학습 이득은 있으나 부족 | scope·lr·`fs_condition` A/B, anti-drift 설계 검토 |
| ≥ 0.48 | 11M 재학습과 다를 바 없다 | 원인 규명(액션 민감도 0? 데이터? lr?) 후 branch A 재검토 |

보조 진단(판정에는 쓰지 않음): 액션 민감도, motion(GT 4.81), 첫 프레임 이탈량(GT 10.19).
참고 DINO: static 0.123 / baseline 11M 0.550 / 11M 재학습 0.481.

## 7. 막혔을 때 참조표

| 증상 | 원인·대처 |
|---|---|

| `torch.utils has no attribute checkpoint` | `lvdm/common.py` 가 임포트 없이 참조. 스크립트 상단에 `import torch.utils.checkpoint`(010 §4.1) |

## 8. 시간이 남으면 (우선순위 순)

1. **`fs_condition` A/B** — `fs_condition=False` 로 짧게 학습해 6fps 조건화가 실제로 이득인지(009 열린질문 2)
2. **`action_dropout_prob` 0.1 vs 0.0** — 1.1B 에서도 CFG 이득이 유지되는지(열린질문 3)
3. **추론 구성 실측** — 25스텝+CFG vs 50스텝 no-CFG 를 홀드아웃에서 모의채점 비교(S6)
4. **scope 비교** — `action_temporal` vs `action_only` 를 같은 스텝 수로(어디를 학습해야 DINO 가 내려가나)
