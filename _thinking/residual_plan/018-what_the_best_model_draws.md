## 0. 한 줄

> **우리 최고 점수는 정지영상을 거의 안 건드려서 나온 것이다.**
> λ=0.15 에서 화면이 바뀌는 양이 평균 **0.28/255 단계** — 사람 눈에 안 보인다.

---

## 1. 실측 — 홀드아웃 3표본 `[측정]`

`|잔차|` = 첫 프레임 대비 픽셀이 바뀐 양의 평균 (0~255 자)

| 표본 | 정답이 움직인 양 | λ=1 로 낸 양 | **λ=0.15 (제출값)** | λ=1 기준 비율 |
|---|---:|---:|---:|---:|
| sample_000000 | 5.89 | 2.02 | **0.28** | 34% |
| sample_000001 | 10.71 | 5.51 | **0.80** | 51% |
| sample_000002 | **23.93** | 2.96 | **0.40** | **12%** |

```
① 제출한 λ=0.15 는 화면을 평균 0.28~0.80 단계 바꾼다.  8비트에서 대부분 0 또는 1 단계다
   → 눈으로 보면 정지영상과 구분이 거의 안 된다
② λ=1 로 키워도 정답 움직임의 12~51% 밖에 안 낸다
③ 가장 크게 움직이는 표본(23.93)에서 비율이 가장 낮다(12%)
```

**③ 이 중요하다. 많이 움직여야 할 때 가장 적게 움직인다.**
012 §3 이 `[추측]` 으로 적어둔 *"팔이 어디로 갈지 모르면 L1 의 최적 답은 가능한 위치들의 평균"*
과 방향이 같다. 평균은 크게 움직이는 경우일수록 작아진다.

⚠ **3표본이다. 홀드아웃이지 eval 이 아니다.** 경향으로만 읽어라.

## 2. 그래서 뭘 알 수 있고 뭘 알 수 없나

**알 수 있는 것**

```
우리가 얻은 −0.0157 은 "잘 그려서"가 아니라 "거의 안 건드려서" 나왔다
λ 곡선이 0.15 에서 골짜기인 것과 정합한다 — 방향이 절반만 맞으면(004 §5: 방향코사인 0.32)
살짝만 미는 것이 안전하다
```

**알 수 없는 것 — 추측으로 메우지 않는다**

```
❌ "제대로 그리면 점수가 훨씬 좋아진다"      → 채점기가 무엇을 벌하는지 우리는 모른다(rule §13)
❌ "잔차를 키우면 된다"                      → λ=0.25 가 이미 손해였다. 실측이 반대다
❌ 어느 성분(DINO/Video/Action)이 좋아졌나   → 확인 수단 없음
```

## 4. 이 관찰이 다음에 무엇을 바꾸나

바로 바꾸는 것은 없다. **다만 하루 3회를 쓸 때 참고할 가설 하나가 생겼다:**

```
[추측]  λ 골짜기가 0.15 근처인 것이 "이 체크포인트의 잔차 크기" 때문이라면,
        잔차 크기가 다른 체크포인트에서는 골짜기 위치가 옮겨간다
        → 새 체크포인트를 낼 때 λ=0.15 를 그대로 쓰면 최적을 놓칠 수 있다
```

**이건 추측이다.** 판정선을 박기 전에는 행동의 근거로 쓰지 않는다.
검증하려면 한 체크포인트에서 λ 를 2점 이상 재야 하고, 그건 하루 예산의 3분의 2다.
**배분이 정해진 뒤에 결정한다** (017 §4).
