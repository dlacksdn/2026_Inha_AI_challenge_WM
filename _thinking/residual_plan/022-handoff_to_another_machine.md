## 3. 옮긴 뒤 순서 (명령 단위)

```bash
# 1. 코드
git clone https://github.com/dlacksdn/2026_Inha_AI_challenge_WM.git
cd 2026_Inha_AI_challenge_WM

# 2. 대회 데이터를 받고 심링크 (경로는 그 기계에 맞게)
ln -s /어디/open open

# 3. 파이썬 환경 — ⚠ §4-① 을 반드시 먼저 읽어라
python -m venv .venv
.venv/bin/pip install -r requirements-lock.txt
.venv/bin/pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128

# 4. 부트스트랩 (OpenSTL clone · 홀드아웃 재생성 · 점검)
bash scripts/branchC/bootstrap.sh .venv/bin/python

# 5. 위 §2 의 .pt 파일들을 같은 경로에 복사

# 6. 로더 점검 — 여기서 숫자가 안 맞으면 멈춰라
CUDA_VISIBLE_DEVICES=0 .venv/bin/python -c "
import sys; sys.path.insert(0,'scripts/branchC')
from loader_c import list_train_episodes, holdout_episode_refs
r=holdout_episode_refs(); a=list_train_episodes(); b=list_train_episodes(exclude=r)
print(len(a),'에피소드 ·',len(set(e.dataset for e in a)),'데이터셋 · 제외',len(a)-len(b))"
#   기대: 10860 에피소드 · 121 데이터셋 · 제외 92
#   ⚠ 5071 / 54 / 0 이 나오면 loader 수정(9262a9b)이 안 들어간 것이다

# 7. 학습 재개
CUDA_VISIBLE_DEVICES=0 .venv/bin/python scripts/branchC/train_c.py \
  --tag <새태그> --steps <목표> \
  --resume artifacts/branchC/train_20260811_0134_long45f/full_043000.pt \
  --wake-step 2000 --micro-batch 2 --accum 8 \
  --dir-loss --tau-alpha 0.1 --lam-c 0.012 \
  --no-ckpt --no-viz
```

**7번 인자는 한 글자도 바꾸지 마라.** 바꾸면 이어붙인 런이 같은 런이 아니게 된다:
- `--wake-step 2000` 없으면 G2 발동 시점이 밀린다
- `--lam-c 0.012` 없으면 손실 가중을 다시 재서 **손실식이 달라진다**
- `--no-ckpt` 는 속도 ×1.31 (BatchNorm 갱신 횟수가 바뀌므로 이 구간 내내 유지)

## 4. 함정 넷 — 모르면 몇 시간을 버린다

### ① 🚨 torch 는 반드시 `+cu128`

```
requirements-lock.txt 는 torch==2.7.1 만 적고 있어 PyPI 기본(cu126)이 깔린다
cu126 에는 sm_120 이 없다 → Blackwell(RTX 5090 / RTX PRO 6000)에서 커널 없이 죽는다
```
확인: `.venv/bin/python -c "import torch;print(torch.__version__, torch.cuda.get_arch_list()[-1])"`
→ **`2.7.1+cu128 compute_120`** 이 나와야 한다 `[측정]`.

이 기계 기준: `python 3.10.20 · torch 2.7.1+cu128 · numpy 1.26.4`

### ② 🚨 경로가 기계마다 다르다 — 이걸로 10일을 날렸다

`holdout_val96/manifest.json` 의 `video_ref` 는 **만든 기계의 절대경로**다(`/home/rils/…`).
다른 기계에서 그대로 비교하면 **교집합이 늘 공집합**이 된다.

```
loader_c.ep_key()        경로 꼬리(data/train/ 이후)로 비교 — 2026-08-11 수정본
rebuild_holdout.py:40    manifest 경로를 현재 기계로 옮긴다 — 원래부터 옳았다
```
> ⚠ 재생성 스크립트는 이 문제를 알고 있었는데 로더는 몰랐다. **새 기계에서 반드시 §3-6 으로 확인하라.**

### ③ 🚨 GPU 지정은 환경변수로만

```
모든 명령 앞에 CUDA_VISIBLE_DEVICES=0
--device cuda 나 torch.cuda.set_device 로 대신하지 마라 — 라이브러리가 몰래 다른 카드를 잡는다
그리고 그 기계에서 쓸 수 있는 카드가 어느 것인지 사람에게 먼저 확인하라
```

### ④ 🚨 제출 킷 규칙 (어기면 평가 제외)

```
킷은 **최종 mp4 를 확정한 뒤 CSV 를 만들 때만** 수정 없이 실행한다
킷의 코드·구조를 참고해 모델을 설계할 수 없다 ("공개 안 된 것처럼 취급")
로컬 채점기를 만들 수 없다.  src/wm_eval/scoring.py 계열은 실행 봉인
eval 데이터로 학습하거나 출력을 고를 수 없다
```
정본: `_thinking/rule/001-competition_guide.md` §12·§13

**판정 (`gates.py` G11, 결과 보기 전에 등록됨)**

| 최저가 | 뜻 | 다음 |
|---|---|---|
| λ=0.25 또는 0.2 | λ* 가 위로 갔다 | 새 체크포인트마다 λ 를 잔차비로 보정한다 |
| λ=0.15 | 안 움직였다 | 체크포인트가 바뀌어도 0.15 를 쓴다 |

근거: 잔차비가 **1.008(11k) → 0.776(43.5k)** 으로 줄었다 `[측정]`. 잔차가 작아지면
같은 실효 세기를 내는 λ 는 커진다 — 추정 0.195.
⚠ **추정이다.** 잔차비는 로컬 지표이고, 이 노선에서 로컬 지표는 점수를 방향까지 틀린 적이 있다.

## 6. 지켜야 할 규율 (이 팀이 여섯 번 데인 방식)

```
· 판정선은 **결과를 보기 전에** 박는다. 바꾸려면 사유를 gates.py CHANGES 에 남긴다
· **로컬 지표로 "점수가 좋아진다"를 말하지 마라.**
  코사인이 더 높은 체크포인트(15,000)가 점수는 더 나빴다(11,000)
  ※ "영상이 볼만해지나"에는 써도 된다 — 그건 코사인이 직접 재는 값이다
· 몇 개 점으로 외삽하지 마라. 3점 외삽으로 세 번 틀렸다
· 규칙 해석에서 우리에게 유리한 쪽을 고르지 마라
· 근거 등급을 붙여라: [코드] / [측정] / [문서] / [추측]
· `_thinking` 은 append-only. 과거 문서를 고치지 말고 새 문서를 쌓아라
· 체크포인트·로그·모델을 폐기하지 마라
· **push 는 사용자만 한다** (작업 기계에 자격증명이 없다)
```

### 이미 반증된 가설 — 같은 길을 다시 파지 마라

```
① "지우기는 잘하고 그리기를 못한다"   → 반대였다
② "불투명도 50~65%로 움직인다"        → 이동비 0.74 인데 방향코사인 0.32
③ "제출 경로에서 신호가 샌다"          → 보존율 1.000
④ "더 학습해도 소용없다"               → 리더보드가 반대를 답했다
⑤ "정지영상을 이기는 λ 가 없다"        → λ=0.15 가 0.0157 이겼다
⑥ "구현은 멀쩡하고 실력 한계다"        → 로더가 데이터 절반을 버리고 있었다 (020)
```
