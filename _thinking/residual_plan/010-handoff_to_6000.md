### ③ A/B 는 코사인으로 판정한다 — 다른 계기가 없기 때문이다

```
출력 = 첫프레임 + λ·r̂ ,  λ 는 추론 때 곱하는 상수 하나 (공짜)
min_λ ‖r − λ·r̂‖² / ‖r‖²  =  1 − cos²
⇒ 크기는 λ 가 흡수한다. 홀드아웃 코사인이 옳은 비교자다
```

⚠ **초판의 근거 한 줄은 철회한다.** *"뭉갬 사다리도 사영이라 최적 λ 가 정확히 1"* 은 **틀렸다.**
009 §1 눈금이 쓰는 뭉갬은 area 축소 + **bilinear** 확대이고 `[코드] probe_blur_and_averaging.py:93-94`
이는 직교사영이 아니다. 홀드아웃 정답 잔차에서 잰 실제 최적 λ 는 **k=2/4/8/16 에서 1.048 / 1.080 / 1.131 / 1.199** `[측정]`.
(사영인 것은 JSON 의 `avgpool_nearest` 열이고 눈금은 그쪽이 아니다.)
⇒ 사다리는 λ=1 로 쟀으므로 **다소 비관적** 쪽이다. **필요 코사인 0.96 이라는 결론은 유지되나 이 근거는 못 쓴다.**

⚠ 그리고 **"규칙 때문에 비교자가 하나뿐"이 아니다.** 킷과 무관한 자체 지표(자체 IDM 등)는

### ⚠ `--steps 6000` 이 아니라 **7000** 인 이유 — G2 가 밀린다 `[측정]`

### 96GB 를 쓰려면 — `--micro-batch 8` 은 **불가능하다** `[측정]`

```
micro-batch ≥ 7 은 OpenSTL MixMlp 의 depthwise conv 에서 32비트 인덱스가 넘쳐
RuntimeError 로 죽는다 (canUse32BitIndexMath). **96GB 여도 동일하다.** 쓸 수 있는 최대는 6
forward-only peak: B=2 → 7.2GiB · B=4 → 14.3 · B=6 → 21.5 · B=7,8 → FAIL
⇒ 예: --micro-batch 4 --accum 4
```

⚠ **유효배치를 고정해도 "수학적 동일"이 아니다.** 번역기에 BatchNorm2d 가 16개 있어
마이크로배치 통계가 바뀌면 forward·gradient 가 바뀐다(mb 2→6 에서 BN 배치평균 17% 변동) `[측정]`.
**A/B 두 팔은 반드시 같은 `--micro-batch` 로 돌려라.**

- **"뭉갬은 사영이라 λ\*=1"**: 틀렸다. 실측 λ\* = 1.048~1.199. 결론 유지, **근거 철회**
