**중간에 갈아끼우는 위험이 더 크다.** 바꾼 것은 데이터 범위와 누수 차단 둘뿐이다.

## 3. ⚠ 정정 — 내 사전 예측이 빗나갔다

결과 보기 전에 이렇게 박아뒀다: *"누수가 사라졌으니 감시 코사인이 떨어져 보일 것"*.

```
수정 전 (누수 섞임)  step ~30,000   코사인 ≈0.545   Δcos ≈0.138   잔차비 ≈1.0
수정 후 (누수 0)     step  32,500   코사인 +0.575   Δcos +0.166   잔차비 0.843
```

**떨어지지 않았다. 올랐다.**

**그렇다고 "수정이 효과 있었다"로도 읽지 않는다.** 한 점이고, 손실은 오히려
0.041 → 0.076 으로 뛰었으며(새 데이터가 들어온 증거), 무엇보다 **로컬 지표로 진척을
주장하지 않는다**는 것이 이 노선의 규율이다(014 §2). 판정은 리더보드로만 한다.

## 4. ⭐ 아침에 낼 것 — 결과 보기 전에 박는다 (G11)

잔차비가 **1.008 → 0.843** 으로 줄었다 `[측정]`. 잔차가 작아지면 최적 λ 는 커진다.

```
step 11,000(구 데이터)  잔차비 1.008 · 최적 λ 0.15  →  실효 세기 0.151
step 32,500(수정)       잔차비 0.843               →  같은 실효 세기면 λ ≈ 0.179
⇒ 0.15 는 이제 작을 수 있다
```

### 제출 (3회, 같은 체크포인트에 λ 3점)

```
아침에 존재하는 **가장 진행된** 체크포인트를 고른다 (감시자가 CSV 를 미리 만들어 둔다)
  lam0.1_step0XXXXX.csv  ·  lam0.15_step0XXXXX.csv  ·  lam0.25_step0XXXXX.csv
```

### 판정 (`gates.py` G11 에 등록됨)

| 최저가 | 뜻 | 다음 |
|---|---|---|
| **λ=0.25** | λ* 가 커졌다. 잔차비 보정 가설이 맞다 | 새 체크포인트마다 λ 를 잔차비로 보정 |
| **λ=0.15** | λ* 가 거의 안 움직였다 | 체크포인트가 바뀌어도 0.15 를 쓴다 |
| **λ=0.1** | λ* 가 작아졌다 | 보정 가설이 틀렸다. 방향을 반대로 |

**왜 학습량 곡선이 아니라 λ 인가**: 오늘 14:00 이후 새 체크포인트가 없다.
남는 문제는 **(체크포인트 × λ) 탐색** 하나이고, 새 데이터 구간에서 λ 를 한 번도 안 재봤다.
λ 를 틀리면 아무리 좋은 체크포인트도 점수가 안 나온다 — step 11,000 에서
λ 0.15 vs 0.25 차이가 **0.0199** 였다.
