## 3. [치명적] 채점 지표가 "큰 백본"을 보상하지 않는다

### 3.1 문서의 주장

> 베이스라인의 UNet은 11M에 불과한 반면 Vid2World는 1.1B 사전학습 UNet을 쓴다 — 약 100배 용량 차이이며, **이것이 DINO·R3D 지표에서 가장 큰 격차를 만들 지점이다.**

이 한 문장이 문서 전체(1순위 선정, 5장 채택안, 실행 계획)의 토대다. 그런데 이 주장에는 근거가 없고, **채점 코드는 반대 방향을 가리킨다.**

### 3.2 채점 코드 실측 (`submission_kit/feature_csv_utils.py`)

세 지표가 실제로 무엇을 보는지 코드에서 직접 확인했다.

```python
# ① Video Feature (30%) — R3D-18
def extract_video_features(videos, model, device):
    x = videos.permute(0, 4, 1, 2, 3).float() / 255.0
    x = F.interpolate(x, size=(videos.shape[1], 112, 112), mode="trilinear", ...)   # ← 112×112 !!
```

```python
# ② DINO (30%) — DINOv2 ViT-S/14, CLS 토큰만
dino_model_name = "vit_small_patch14_dinov2.lvd142m"
...
def _normalize_image_model_output(output):
    if output.ndim == 3:
        output = output[:, 0]        # ← CLS 토큰 1개. 패치 토큰 전부 폐기
```

```python
# ③ Action (40%) — SO100ActionExtractor.forward
def forward(self, video):
    x = self.stem(video); x = self.encoder(x)
    x = x.mean(dim=(-1, -2))         # ← 공간 차원 전역 평균 풀링. 위치정보 소멸
    x = rearrange(x, "b c t -> b t c")
    x, _ = self.temporal_model(x)    # BiGRU
    return self.head(x)              # 프레임별 6D 절대 관절각
```

### 3.3 무엇이 문제인가

| 지표 | 실제로 보는 것 | 1.1B 사전학습 프라이어가 주는 이득 |
|---|---|---|
| Video 30% | 320×512를 **112×112로 삼선형 축소**한 클립 | 거의 없음. 고주파 디테일이 축소 과정에서 소멸 |
| DINO 30% | 프레임당 **CLS 토큰 384차원 1개**의 코사인 거리 | 제한적. 전역 의미 기술자라 장면 구성만 맞으면 포화 |
| Action 40% | 공간 전역 평균 풀링 후 BiGRU → **절대 관절각** | 없음. 픽셀 사실성이 아니라 팔의 기하학적 자세가 관건 |

즉 세 지표 **모두** 저해상도이거나 전역 통계다. 인터넷 스케일 영상 프라이어가 주는 것(텍스처 사실성, 조명, 고주파 디테일)은 채점 파이프라인이 계통적으로 버리는 정보다.

**"100배 용량 = 점수 격차"는 비약이다.** 용량과 점수 사이에 인과 경로가 필요한데, 문서는 그 경로를 제시하지 않았고 코드는 그 경로가 좁다고 말한다.

### 3.4 문서가 반드시 했어야 할 실험 (누락)

큰 백본을 주장하기 전에 **바닥값 3개**를 재야 한다. 전부 GPU 몇 분이면 끝난다.

1. **정지 반복(static repeat)**: 시작 프레임을 16번 복사한 mp4 → 점수?
   - 카메라 고정 · 2.67초 · 배경 대부분 불변이므로 DINO/R3D 60% 중 상당 부분이 여기서 이미 확보될 가능성이 높다.
2. **베이스라인 11M 재현 점수**
3. **정답 영상 자체를 채점** (train 홀드아웃) → 도달 가능한 하한

`static repeat`과 `베이스라인` 사이의 간격이 좁다면, 문서의 전략은 통째로 재설계 대상이다. 이 숫자 없이는 "100배 용량" 주장은 **반증 불가능한 서사**에 불과하다.

## 4. [치명적] 추론 1시간 예산 — 문서가 ✅로 표시했으나 실제로는 초과

### 4.1 1차 출처 수치

DynamiCrafter 공식 저장소가 자기 모델의 추론 비용을 공개한다 ([GitHub](https://github.com/Doubiiu/DynamiCrafter), *"GPU Mem. & Inference Time (A100, ddim 50steps)"*):

| 해상도 | GPU 메모리 | 추론 시간 |
|---|---|---|
| 256×256 | 11.9 GB | 10 s |
| **320×512** | **12.8 GB** | **20 s** |
| 576×1024 | 18.3 GB | 75 s |

베이스라인 평가 설정도 정확히 50 스텝이다 (`configs/eval/inha_submission_eval_11M.yaml`):

```yaml
ddim_kwargs:
  ddim_steps: 50
  unconditional_guidance_scale: 1.0     # ← CFG 꺼짐 = 스텝당 UNet 1회
  guidance_rescale: 0.7
  ddim_eta: 1.0
```

### 4.2 계산

```
[기준] A100, 320×512, 16프레임, DDIM 50스텝, 배치 1
   216 샘플 × 20 s = 4,320 s = 72분   →  이미 60분 예산 초과 (1.2×)

[대회 GPU 보정] RTX PRO 6000 Blackwell vs A100 (BF16 dense)
   제3자 스펙 비교는 A100 312 TFLOPS vs RTX PRO 6000 125 TFLOPS를 제시한다.
   FP8/FP4 경로를 제외한 보수적 추정 배율을 0.4×~0.8×로 잡으면
   샘플당 25 ~ 50 s  →  216 샘플 = 90 ~ 180분

[배치 이득] 현실적 1.2~2.0× (근거는 4.3)
   →  45 ~ 150분.  중앙값 부근에서 예산 초과
```

**문서의 게이트 표는 Vid2World의 G5(추론)를 ✅로 표시했다. 근거 없는 통과 판정이다.**

### 4.3 [치명적] "배치 8~16 → 유효 예산 2~3분"은 계산 오류

문서 1장의 완화 조건:

> 실제로는 96GB VRAM에서 배치 8~16개를 동시 생성할 수 있으므로 유효 예산은 샘플당 약 2~3분 수준으로 늘어난다.

세 가지가 틀렸다.

1. **배치는 예산을 늘리지 않는다.** 배치가 늘리는 것은 GPU **이용률**이지 총 연산량이 아니다. 216샘플의 총 FLOPs는 배치 크기와 무관하게 동일하다. "샘플당 2~3분"이라는 표현은 벽시계 예산이 8~16배로 늘어난다는 뜻이 되는데, 그런 일은 일어나지 않는다.
2. **이 모델은 이미 연산 포화 상태다.** 배치 1이어도 UNet은 16프레임 × 40×64 잠재를 한 번에 처리한다. 시간축이 배치 차원으로 접히므로 유효 배치는 이미 16이다. 커널 런치 오버헤드가 지배적인 소형 모델과 다르다. 추가 배칭의 현실적 이득은 **1.2~2배**지 8~16배가 아니다.
3. **VRAM 산술도 과대**하다. 공식 수치가 배치 1에 12.8 GB이므로 96 GB에는 **6~7개**가 들어간다. 16개는 들어가지 않는다.

### 4.4 그리고 문서의 핵심 제안이 이 비용을 **2배로 만든다**

베이스라인은 지금 `unconditional_guidance_scale: 1.0`, 즉 **guidance를 쓰지 않는다**(스텝당 UNet 1회). 문서가 최우선으로 밀고 있는 action CFG를 켜면 조건부/무조건부 두 번을 평가해야 하므로 **NFE가 정확히 2배**가 된다.

```
액션 CFG 적용 시:  90 ~ 180분  ×  2  =  180 ~ 360분   (예산의 3~6배)
```

문서 어디에도 이 비용이 언급되지 않는다. "재학습 없이 얻는 점수"라고 표현했지만, **무료가 아니라 추론 예산을 두 배로 먹는다.** 그리고 λ 스윕 1포인트마다 216샘플 전체 생성이 필요하다.

> **해결 가능한가**: 가능하다. 스텝 50→10~16, few-step 샘플러(LCM/DMD 계열), fp8, `torch.compile`, 배칭을 병행하면 들어간다. 다만 그것은 **문서에 없는 별도의 큰 작업**이며, "✅ 통과"로 처리할 사안이 아니라 **최우선 실측 항목**이다.

## 5. [치명적] 학습 예산 — 산술적으로 불가능

### 5.1 문서의 대응책

> 논문의 ablation이 30k step으로 수행된 점을 근거로 **step 수 축소 + 부분 파인튜닝** 전략이 필요하다.

즉 "100k → 30k로 줄이면 된다"는 것이다. 실제로 계산해 보자.

### 5.2 역산

```
[원논문 처리량]
   100,000 step = 7일 × 4 × A100 = 28 A100-day
   → 3,571 step / A100-day

[대회 예산의 A100 환산]
   4일 × 1 × RTX PRO 6000
   RTX PRO 6000 ÷ A100 (BF16 dense) ≈ 0.4 ~ 0.8×   (보수적 범위)
   → 1.6 ~ 3.2 A100-day

[살 수 있는 step 수]
   3,571 × (1.6 ~ 3.2) = 5,700 ~ 11,400 step
```

| | step | 판정 |
|---|---:|---|
| 원논문 본 실험 | 100,000 | 예산의 **9~18배** |
| 원논문 ablation (문서의 목표) | 30,000 | 예산의 **2.6~5.3배** |
| **실제 예산으로 가능** | **5,700 ~ 11,400** | — |

**문서가 제시한 완화책(30k step)조차 예산 밖이다.** 배율 추정에 불확실성이 있지만(→ 8장 미확인 항목), 0.4×를 쓰든 0.8×를 쓰든 결론은 뒤집히지 않는다.

부분 파인튜닝(시간축 레이어 + 액션 MLP만)은 역전파 비용을 줄이지만, **순전파는 여전히 전체 1.1B를 통과**하므로 절감은 대략 30~40%에 그친다. 격차 3~5배를 메우지 못한다.

### 5.3 추가로: 4일은 "한 번의 학습" 예산이다

규칙은 최종 모델 학습이 4일 안에 끝나야 한다고 말한다. 그런데 문서 5.2절의 실행 계획은 v1, v2, λ 스윕, 데이터 필터링까지 6단계다. 참고로 베이스라인 자신의 학습 설정은 이미 이렇게 되어 있다:

```yaml
max_steps: 100000
max_time: "00:48:00:00"        # 48시간
batch_size: 1
accumulate_grad_batches: 2      # 유효 배치 2
```

11M 모델이 유효 배치 2로 48시간을 쓰도록 설계되어 있다. 100배 큰 모델을 같은 시간에 밀어 넣는다는 계획은 재검토가 필요하다.

## 6. [치명적] 추천안은 사실상 Vid2World를 쓰지 않는다

여기가 문서의 구조적 결함이다.

### 6.1 문서가 버리는 것과 남기는 것

문서 5.1절 채택안:

```
causalization                 →  도입하지 않음
UNet 11M 스크래치             →  DynamiCrafter 1.1B 사전학습 가중치
액션 조건화                    →  Vid2World식 프레임별 액션 MLP 주입
액션 CFG 없음                  →  학습 중 액션 드롭아웃 + 추론 시 λ 스윕  ★
```

- **causalization을 버린다** = Vid2World 논문의 주된 기여를 버린다는 뜻이다. 논문 제목의 "Interactive World Models"가 바로 그것이다.
- **가중치를 못 쓴다** — 공개된 8종 체크포인트는 전부 causal화된 모델이다. causalization을 제거하면 이 가중치들은 로드 대상이 아니다. 게다가 RT-1(Google 로봇, 다른 카메라·다른 액션 공간)이라 도메인도 맞지 않는다.
- 남는 것은 **"프레임별 액션 임베딩을 가산하고, 학습 때 드롭아웃해서 CFG를 쓴다"** 한 줄이다.

### 6.2 그런데 그 한 줄은 베이스라인에 이미 있다

`baseline/challenge_kit/configs/train/inha_action_diffusion_11M.yaml`:

```yaml
unet_config:
  params:
    action_conditioned: True
    action_dims: 6
    action_dropout_prob: 0.0      # ← 이미 배선되어 있고, 확률만 0으로 꺼져 있다
```

**액션 드롭아웃은 이미 구현되어 있다.** 문서가 "Vid2World에서 이식할 ★핵심 부품"이라고 표시한 것이, 실제로는 베이스라인 코드에서 **숫자 하나를 0에서 0.1로 바꾸는 일**이다.

### 6.3 그래서 무엇이 문제인가

"1순위 모델: Vid2World"라는 문장이 성립하지 않는다.

- 방법론(causalization)은 쓰지 않는다
- 가중치는 쓸 수 없다
- 남은 기법은 대회 베이스라인에 이미 들어 있다
- 실제로 쓰는 것은 **DynamiCrafter 사전학습 가중치**뿐인데, 그것은 Vid2World가 아니라 베이스라인이 이미 상속한 계보다

문서가 실제로 권고하는 바를 정확히 쓰면 이렇게 된다:

> **베이스라인 UNet을 DynamiCrafter 1.1B 사전학습 가중치로 교체하고, `action_dropout_prob`를 켠 뒤 추론에서 λ를 스윕한다.**

이것은 타당한 계획일 수 있다. 하지만 이것은 **모델 선정이 아니라 설정 변경**이며, 3~5장에서 본 세 가지 예산·지표 문제를 정면으로 안고 있다. 논문 서베이 형식의 "1순위/2순위/탈락" 표는 이 실체를 가린다.

## 7. [중대] 그 밖의 논리·사실 결함

### [중대-1] λ 스윕의 근거는 추측이다 — 추출기는 "움직임"이 아니라 "절대 자세"를 읽는다

문서:

> λ를 키우면 **행동이 과장되게 표현돼 Action MAE가 내려가고**, 너무 키우면 영상이 붕괴해 DINO·R3D가 나빠진다.

`action_extractor.py`를 읽으면 이 메커니즘이 성립하지 않는다.

- 추출기는 3D CNN → **`x.mean(dim=(-1,-2))` 공간 전역 평균 풀링** → BiGRU → 프레임별 **6차원 절대 관절각**을 회귀한다.
- 즉 광학 흐름이나 프레임 차분을 읽는 장치가 아니라, **각 프레임에서 팔이 어떤 자세인지**를 회귀하는 역기구학 모델이다.
- MAE는 정규화 공간에서의 **절대값 오차**다 (`feature_csv_utils.py:351`).

따라서 "과장하면 MAE가 내려간다"는 성립하지 않는다. 자세를 **과장**하면 예측 관절각이 정답에서 **멀어진다**. λ의 실제 효과는 "모델이 조건을 무시하지 않게 만드는" 지점까지만 단조롭게 유익하고, 그 이후에는 MAE가 **올라간다**고 보는 편이 타당하다.

추가로, 공간 전역 평균 풀링 때문에 추출기는 그리퍼 위치를 정밀하게 국소화하지 못하고 전역 특징 통계에 반응한다. 즉 λ에 대한 반응이 **비단조적이고 예측 불가능**할 가능성이 크다.

> λ 스윕 자체는 해볼 가치가 있다. 문제는 문서가 이것을 **"유일한 손잡이"이자 "재학습 없이 얻는 점수"**로 격상시켜 실행 계획 3순위에 올려놓았다는 점이다. 검증되지 않은 가설에 계획의 무게중심을 두었다.

### [중대-2] eval 액션 분포가 train과 다르다 — 두 문서 모두 놓쳤다

eval 216개 `.npy` 전부와 `so100_action_statistics.json`을 직접 대조 계산했다.

```
train 통계로 정규화한 eval 액션의 z-score

  차원        0      1      2      3       4       5
  ---------------------------------------------------
  z 평균    0.05  -0.63  -0.37   0.06   +1.50   -0.04
  z 표준편차 1.11   1.49   1.37   0.53    0.65    0.58
```

| 발견 | 함의 |
|---|---|
| **dim 4 (`wrist_roll`)가 train 평균에서 +1.50σ 이탈** | eval은 전체 128개 데이터셋의 균등 표본이 **아니다**. 특정 부분집합에서 나왔을 가능성이 높다 |
| dim 3·5의 z 표준편차가 0.53·0.58로 좁음 | eval의 동작 다양성이 train보다 좁다 |
| dim 1·2의 z 표준편차가 1.49·1.37로 넓음 | 반대로 어깨·팔꿈치는 더 넓게 분포 |
| 클립 내 z 변화폭 중앙값: dim4 = 0.174 (최소) | wrist_roll은 16프레임 동안 **거의 움직이지 않는다** |

**왜 치명적인가**: 128개 데이터셋에 대해 균등하게 학습한 모델은 wrist_roll을 train 평균 쪽으로 회귀시킨다. 그런데 eval의 정답은 평균에서 1.5σ 떨어진 곳에 있고, 클립 내내 거의 그 값에 머문다. 결과적으로 **Action MAE(40%)에서 계통적이고 상수에 가까운 손실**이 발생한다.

이것은 λ 스윕보다 점수 기여가 클 가능성이 높은, **측정 가능한 구체적 문제**다. 두 문서 모두 언급이 없다.

> 규칙 주의: eval 통계를 보고 **학습 데이터 부분집합을 고르는 것**은 "eval을 어떤 형태로도 학습에 사용 금지" 조항과 회색지대에 있다. 안전한 경로는 액션 조건을 강하게 따르는 모델을 만드는 것이지, eval 분포에 맞춰 학습 데이터를 고르는 것이 아니다. 이 판단은 팀이 명시적으로 내려야 한다.

### [중대-3] 라이선스 게이트 표가 잘못된 대상을 통과시켰다

문서 게이트 표: `Vid2World | G1 라이선스 ✅ Apache-2.0`

그런데 실제로 배포물에 실리는 가중치는 **DynamiCrafter**다. 확인 결과:

| 대상 | 실제 라이선스 | 규칙 부합 |
|---|---|---|
| Vid2World **코드** | Apache-2.0 | ✅ |
| Vid2World **가중치** (안 씀) | 저장소 기준 Apache-2.0 | — |
| DynamiCrafter **코드** | Apache-2.0 | ✅ |
| **DynamiCrafter 가중치** ([HF 카드](https://huggingface.co/Doubiiu/DynamiCrafter_512)) | **라이선스 태그 없음**. 명시: *"it can only be used for personal/research/non-commercial purposes"* | ⚠️ **회색** |

규칙이 요구하는 것은 "MIT, Apache 2.0, CC BY, CC BY-NC **등**" 비상업 이용이 허용된 라이선스다. DynamiCrafter의 "research/non-commercial only"는 **정신상으로는 부합**하지만 열거된 표준 라이선스가 아니고, **HF 카드에 라이선스 태그 자체가 없다**.

**판정**: 수상 취소 사유가 될 가능성은 낮다. 베이스라인 자체가 DynamiCrafter 계보이므로 주최측이 사실상 승인한 셈이고, 규칙은 비상업을 명시적으로 허용한다. 문서의 결론("리스크 낮음")은 **결과적으로 옳다.**

**그러나 과정이 틀렸다.** 문서는 코드 라이선스와 가중치 라이선스를 구분하지 않았고, 게이트 표에 Vid2World의 Apache-2.0을 적어 놓고 실제로는 다른 라이선스의 가중치를 쓴다. 소스코드 제출 시 라이선스 고지가 필요하므로, **팀은 이 구분을 정확히 문서화하고 필요하면 주최측에 사전 문의**해야 한다.

### [중대-4] 아키텍처 교체가 "가중치 로드"로 축소 표현됨

문서 실행 계획 2단계: "DynamiCrafter 1.1B 가중치 로드 + 액션 MLP 이식"

실제 차이:

| 항목 | 베이스라인 11M | DynamiCrafter 1.1B | 일치 |
|---|---|---|:--:|
| `model_channels` | **32** | 320 | ❌ 10배 |
| `channel_mult` | **[1, 2, 3]** | [1, 2, 4, 4] | ❌ 레벨 수도 다름 |
| `attention_resolutions` | **[4, 2]** | [4, 2, 1] | ❌ |
| `in_channels` / `out_channels` | 8 / 4 | 8 / 4 | ✅ |
| `context_dim` | 1024 | 1024 | ✅ |
| `image_size` (잠재) | [40, 64] | [40, 64] | ✅ |
| `temporal_length` | 16 | 16 | ✅ |

**좋은 소식**: 하이브리드 조건화 배선(`in_channels: 8` = 잠재 4 + 이미지 4), `context_dim`, 잠재 해상도, 시퀀스 길이가 모두 맞는다. 계보 호환성은 문서 말대로 진짜다.

**나쁜 소식**: UNet 본체는 로드가 아니라 **설정 교체**이고, 액션 분기(`action_conditioned` 경로)를 320채널 폭에 맞춰 **재작성**해야 한다. 그리고 DynamiCrafter 사전학습 가중치에는 액션 분기가 **존재하지 않으므로** 그 부분은 스크래치 학습이다. "이식"보다 무거운 작업이다.

### [중대-5] 6fps 도메인 격차 미언급

- 학습 데이터: **6 fps** (원본 30fps를 5배 다운샘플)
- DynamiCrafter 사전학습: **8 fps** 자연 영상
- 베이스라인 설정: `default_fs: 10`, `fs_condition: false` — **fps 조건화가 꺼져 있다**

프레임 간 변위가 사전학습 분포보다 크다. 인터넷 영상 프라이어가 이 대회 데이터에 얼마나 전이될지는 자명하지 않으며, 문서는 "규격이 우연이 아닐 정도로 정확히 겹친다"고만 적었다. 겹치는 것은 해상도와 프레임 **수**이지 시간 해상도가 아니다.

### [중대-6] 대안 탐색 누락 — LeRobot v0.6.0

문서 조사일(2026-07-19) 기준으로 **12일 전인 2026-07-07**에 [LeRobot v0.6.0](https://huggingface.co/blog/lerobot-release-v060)이 릴리스되었고, 그 헤드라인이 **월드 모델 3종**이다.

| 모델 | 성격 | 비고 |
|---|---|---|
| **VLA-JEPA** | Qwen3-VL-2B 기반, 잠재 미래 예측 | 픽셀 생성 없음 → 본 대회 부적합 |
| **LingBot-VA** | 자기회귀 video-action 모델 | 추론이 24~32GB GPU 1대에서 가능 |
| **FastWAM** | ~5B 영상 전문가 + 소형 액션 전문가 | 배포 시 영상 생성 생략 → 부적합 |
| MolmoAct2 | **SO-100/101 제로샷 체크포인트**, bf16 12GB | 정책 모델이지 월드 모델은 아님 |

그 밖에 문서가 다루지 않은 2026년 항목: [Cosmos 3 (2606.02800)](https://arxiv.org/pdf/2606.02800), [RynnWorld-Teleop (2607.06558)](https://arxiv.org/pdf/2607.06558), [RepWAM (2606.13674)](https://arxiv.org/pdf/2606.13674), DSWAM (2607.04927), HiMem-WAM (2606.10363), 그리고 [`nvidia/Cosmos-Predict2-2B-Sample-Action-Conditioned`](https://huggingface.co/nvidia/Cosmos-Predict2-2B-Sample-Action-Conditioned).

**공정하게 말하면**: 이 중 상당수는 본 대회 제약(픽셀 생성 필수, 4 GPU-day, 1시간 추론)에 걸려 탈락한다. LingBot-VA 정도가 검토 가치가 있다. **Vid2World보다 명확히 나은 대안을 찾지는 못했다.**

**그러나** SO-100 대회를 위한 월드 모델 조사가 12일 전 SO-100 생태계의 메이저 릴리스를 통째로 누락한 것은 조사 절차의 구멍이다.

### [중대-7] "월드 모델 계열만" 게이트는 규칙이 아니라 문서의 창작이다

문서는 Wan 2.2 / LTX-Video / CogVideoX / HunyuanVideo를 **"월드 모델이 아님 (대회 철학 위반)"** 으로 탈락시켰다.

규칙 원문에 그런 조항은 없다. 제출물은 mp4 216개에서 뽑은 feature CSV이고, 채점은 0.3/0.3/0.4 산식뿐이다. 채점기는 모델의 계보를 묻지 않는다.

동시에 문서 자신의 채택안은 **DynamiCrafter(순수 영상 생성 모델)에 액션 조건을 붙인 것**이다. 즉 자기 기준을 자신에게는 적용하지 않았다. "액션 조건을 붙인 영상 생성 모델"이 허용된다면 Wan 2.2에 같은 처리를 하는 것도 같은 자격이다.

Wan 2.2가 실제로 탈락해야 한다면 그 근거는 **철학이 아니라 연산량**이어야 한다(5B는 4 GPU-day에 안 들어간다). 정량 근거를 쓰지 않고 철학을 쓴 탓에, 이 게이트는 **검증 가능한 후보를 근거 없이 배제**한다.

### [중대-8] 탈락 판정 재심 — iVideoGPT

문서: "해상도가 64×64 또는 256×256이다. 320×512로 업스케일하면 DINOv2·R3D feature 거리에서 **구조적으로 불리**하다."

3장에서 본 대로 **R3D-18은 112×112로 축소해서 채점**한다. 256×256에서 생성한 영상을 320×512로 올려도 R3D 입력 단계에서 다시 112×112로 내려간다. **불이익이 문서가 상정한 것보다 훨씬 작다.**

DINO는 518×518로 리사이즈+패딩하므로 여기서는 실제로 손해가 있지만, CLS 토큰 코사인 거리라 역시 완충된다.

**판정**: iVideoGPT의 탈락 결론 자체는 다른 이유(토큰 자기회귀의 액션 정밀도, 도메인)로 유지될 수 있으나, **문서가 제시한 근거는 정량적으로 틀렸다.** 문서는 "구조적으로 불리"라고 단정했을 뿐 채점 해상도를 확인하지 않았다.

## 10. 종합 평결

# ② 조건부 유지

단, 조건이 가볍지 않다. 정확히 말하면:

> **기술 방향(DynamiCrafter 계열 사전학습 백본 + 액션 드롭아웃/CFG)은 유지한다.
> "Vid2World를 1순위 모델로 선정한다"는 프레이밍은 폐기한다.**

### 왜 기각(③)이 아닌가

- 문서의 **사실 수집은 대체로 정확**했다 (2장, 14개 항목 검증 통과).
- **더 나은 대안을 찾지 못했다.** 8개 이상의 새 검색으로 2025–2026 후보를 훑었지만, 4 GPU-day · 1시간 추론 · 오픈 가중치 · 320×512 픽셀 생성이라는 제약을 Vid2World/DynamiCrafter 계보보다 잘 만족하는 모델은 없었다.
- **탈락 판정들의 결론은 대체로 옳다** (근거가 부실한 경우는 있어도).
- 백본 계보 호환성(`in_channels 8`, `context_dim 1024`, 잠재 40×64, 길이 16)은 실제로 맞아떨어진다.

### 왜 무조건 유지(①)가 아닌가

세 개의 치명적 결함이 계획의 **근거·예산·정체성**을 각각 무너뜨린다.

1. **근거**: 채점 지표 3종이 전부 저해상도·전역 특징이라, "100배 용량 → 점수 격차"라는 핵심 논거가 코드상 뒷받침되지 않는다 (3장)
2. **예산**: 추론은 이미 1.2~3배 초과이고 액션 CFG가 이를 2배로 늘린다 (4장). 학습은 목표치 30k step조차 예산의 2.6~5.3배다 (5장)
3. **정체성**: 남는 기법이 베이스라인에 이미 구현되어 있어(`action_dropout_prob`), "Vid2World 채택"은 모델 선정이 아니라 설정 변경이다 (6장)

### 필수 수정사항 8가지

| # | 수정 | 우선순위 |
|---|---|:--:|
| 1 | **바닥값 3개를 먼저 측정한다** — static repeat / 베이스라인 / 정답 영상 upper bound. 이 숫자 없이 백본 확장을 결정하지 말 것 | **0순위** |
| 2 | **추론 예산을 실측한다** — 실제 GPU에서 1.1B UNet의 샘플당 시간을 스텝 수·배치별로 재고, 60분 안에 들어가는 (스텝, 배치, CFG 여부) 조합을 먼저 확정한 뒤 학습을 설계한다 | **0순위** |
| 3 | 게이트 표에서 Vid2World의 **G5 ✅를 ⚠️로 정정**하고, "배치 8~16 → 유효 예산 2~3분" 문장을 삭제한다 | 높음 |
| 4 | 학습 계획을 **5,700~11,400 step 예산**으로 다시 세운다. 30k step 전제는 폐기 | 높음 |
| 5 | **eval 액션 분포 이탈(wrist_roll +1.5σ)** 을 리스크 표에 추가하고 대응을 설계한다 (중대-2) | 높음 |
| 6 | λ 스윕의 근거를 "추출기가 움직임을 읽는다"에서 **"추출기는 절대 관절각을 회귀한다"** 로 정정하고, 기대 효과를 하향 조정한다 | 중간 |
| 7 | 라이선스 표를 **코드/가중치로 분리**하고, DynamiCrafter 가중치의 "research/non-commercial only"를 명시한다 | 중간 |
| 8 | **중형 모델 스크래치 학습(≈100–400M)을 정식 대안으로 표에 올린다.** 예산 안에서 수렴까지 학습 가능한 유일한 크기대이며, 지표가 전부 저해상도인 이 대회에서 1.1B-부분적응보다 우위일 가능성이 실재한다 | 중간 |

### 재평결 조건

수정사항 1·2를 측정한 뒤:

- **static repeat과 베이스라인의 격차가 작다면** → 대형 백본 노선은 근거를 잃는다. 평결은 **③ 기각**으로 전환하고, 액션 충실도(40%)에 특화된 중형 모델 + OSCAR식 URDF 스켈레톤 보조 조건으로 재설계한다.
- **1.1B가 60분 예산 안에 들어가지 않는다면** → few-step 증류가 별도 프로젝트가 되므로, 4주 일정에서 현실적이지 않다. 역시 **③**.
- 둘 다 통과하면 → **① 유지**로 승격.

### 마지막 한 마디

문서의 가장 큰 문제는 틀린 사실이 아니다. 사실은 대체로 맞다.

문제는 **검증 가능한 숫자를 재지 않은 채 서사로 결론을 지지했다는 것**이다. "100배 용량", "규격이 우연이 아닐 정도로 겹친다", "재학습 없이 얻는 점수" — 셋 다 매력적이지만 셋 다 측정되지 않았고, 실제로 측정해 보니 셋 다 문서가 기대한 방향과 다르거나 반대였다.

역설적으로 문서 자신이 답을 갖고 있다. 실행 계획 0단계가 **"로컬 모의채점 루프 구축 — 최우선"** 이다. 옳다. 다만 그것을 **모델을 고른 뒤**가 아니라 **고르기 전에** 했어야 한다.
