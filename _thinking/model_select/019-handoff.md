## 2. ⭐ 8/1 저녁에 바뀐 것 두 가지 (이게 설계를 바꾼다)

### ① 해상도는 목표가 아니라 증폭기다

```
  방향이 섞임(A-1)                       방향은 맞고 세기만 약함(A-2)
  α \ k    1       2       4       8      α \ k    1       2       4       8
  0.50  +0.030  +0.018  +0.016  +0.014    0.50  −0.020  −0.014  −0.009  −0.002
  0.35  +0.042  +0.026  +0.022  +0.017    0.35  −0.013  −0.011  −0.007  −0.002
  0.25  +0.046  +0.031  +0.026  +0.019    0.25  −0.010  −0.008  −0.005  −0.002
        ▲ 해상도를 올리면 **더 나빠진다**        ▲ 25% 세기로도 이긴다
```

**같은 α·같은 k 인데 부호가 반대다.** 차이는 틀린 성분이 "남의 움직임"인가 "그냥 작음"인가뿐.

**우리 확산모델은 나쁜 쪽에 있다** (α≈0.5, "절반은 맞고 절반은 남의 움직임").
그래서 사전 등록한 *"잔차 노선 재검토"* 판정선이 발동했다.

**재검토 결과 — 노선 유지, 근거 변경.**
결정론 회귀는 같은 입력에 항상 같은 답을 내므로 **방향이 무작위로 흔들리지 않는다.**
조건부 평균은 방향을 바꾸지 않고 세기만 줄인다 → **구조적으로 A-2 쪽을 향한다.**
그리고 A-2 쪽은 **25% 세기로도 이길 만큼 관대하다.**

⚠ **이건 이론적 기대이지 측정이 아니다.** 실제로 학습해 봐야만 안다.
자세히: [figure/006](../figure/006-direction_over_resolution.md)

### ② 픽셀 손실이 우리를 잘못된 방향으로 끈다

```
  같은 영상, 같은 96표본
    픽셀 L1     12.343 → 11.054   −10.4% 개선.  96/96 전부 개선
    채점 DV      0.0943 →  0.1132  +20% 악화.   t=+9.99
```

**픽셀공간의 평균은 특징공간의 평균이 아니다.** 픽셀을 평균내면 DINOv2 특징공간에서
자연 이미지 곡면을 벗어난 흐릿한 점으로 가고, 채점기가 심하게 벌한다.

**결정론 회귀가 L1 으로 만드는 출력이 바로 그 "조건부 평균"이다.**
⇒ **픽셀 항은 붕괴를 막는 닻으로만 두고, 최적화의 주도권은 채점기 손실에 준다.**
자세히: [figure/005](../figure/005-ksample_closed.md)

## 3. C 설계서(8/2)에 넣어야 할 것

### 반드시 답해야 하는 질문 — 우선순위 순

1. ⭐ **방향을 어떻게 맞히나** — 이게 1순위가 됐다
   - 행동 16단계를 프레임별로 어떻게 잔차에 연결하나 (per-frame FiLM/AdaLN)
   - 방향이 섞이는 것을 막는 구조적 장치가 있나
2. **손실 구성과 λ**
   - `L_pixel(L1) + λ_d·L_DINO(1−cos, CLS 384차원) + λ_a·L_action(MAE)`
   - **λ 는 값이 아니라 gradient norm 정렬로 잡는다.** 세 항의 gradient norm 과
     상호 코사인 유사도를 매 스텝 로깅하고, 음의 코사인이 지속되면 PCGrad
   - 픽셀 항 비중을 낮게 (§2-②)
3. **백본과 해상도**
   - 3D conv + spatiotemporal attention / DiT / UNet
   - 출력 해상도 (H1 은 가설이지만, 낮으면 확실히 손해다)
4. **중단 조건과 체크포인트 선택 기준** — 판정선을 **학습 시작 전에** 수치로 고정
5. **재현 검증용 단일 스크립트 구조** (8/10~ 에 필요)
6. **롤백 조건** — 어떤 관측이 나오면 어떤 결정을 되돌리나

### 손실 배선의 확정된 사실 (코드로 확인)

| 항목 | DINO (30%) | R3D (30%) | **Action (40%)** |
|---|---|---|---|
| 시간축을 보나 | **아니다.** 프레임별 CLS | 그렇다 | **그렇다.** Conv3d + 양방향 GRU |
| **프레임 서브샘플링** | ✅ 가능 (불편 추정량) | ❌ 불가 | ❌ **불가. 16프레임 전부** |
| 크기 | ViT-S 22M (동결) | R3D-18 33M (동결) | **4.59M (동결)** |
| 입력 | 518×518, 위아래 37.5% 검은 패딩 | 112×112 로 **찌그러뜨림** | 320×512 그대로 |

**⇒ 서브샘플링으로 아낄 수 있는 것은 DINO 뿐이다.**
016·017 이 적은 "k=4 로 비용 1/4" 은 DINO 에만 해당한다.

**⚠ 스케일 규약 함정**: `preprocess_images()` 는 **0~255 스케일**을 받아 `/255*2−1` 한다.
그런데 데이터로더(`batch["video"]`)는 **이미 [−1,1]** 이다.
손실에 넣기 전 **`(x+1)/2*255` 로 되돌려야 한다.** 안 그러면 조용히 잘못된 것을 최적화한다.

### 재사용할 수 있는 것 / 새로 써야 하는 것

**그대로 쓴다**

```
  ldwma.lightning.data_modules.lerobot_so100.SO100DataModule
      batch["video"]  (B, 3, 16, 320, 512)  float [−1,1]   ← **채점 공간과 완전히 같은 전처리**
      batch["act"]    (B, 16, 6)            정규화됨
  src/wm_eval/scoring.py                  로컬 채점기
  scripts/branchB/compare_reports.py      표본별 짝지은 t 검정
  scripts/make_submission.sh              공식 킷 무수정 호출
```

**새로 쓴다** — branch B 는 DynamiCrafter 잠재확산을 config 로 돌린 것이라
**C 는 config 변경이 아니라 새 모델 + 새 학습 루프**다.

```
  ① 모델      잔차 회귀기 (FiLM/AdaLN 행동 주입, 잔차 헤드 zero-init)
  ② 학습 루프  평범한 PyTorch 또는 Lightning
  ③ 손실      위 구성
  ④ 추론      홀드아웃/eval 생성 → mp4
```

규모 감각: 문헌의 비슷한 시스템이 40M~176M 파라미터에 H200 1장 18시간.
**우리 예산(5090 32GB, 학습 ≤ 4일)에 충분히 들어간다.**

### ⚠ C 학습 **전에** 반드시 할 것

**누수 없는 홀드아웃으로 평가한다.** 기존 `artifacts/holdout` 은 96개 중 약 95%가
학습에 쓰인 에피소드다(코드로 확정). 지금까지는 결론이 전부 "학습 데이터에서조차 진다"는
보수적 방향이라 무해했지만, **C 는 이기려고 만드는 것이라 이기는 순간
암기와 일반화를 구분할 수 없다.**

```
  artifacts/holdout_val96/      이미 만들어 뒀다 (val split 554개에서만 뽑음, 새너티 통과)
  생성기: scripts/branchC/build_holdout_val.py
```

**⚠ C 의 학습 config 가 `val_fraction`·`seed`·`traj_len`·`downsample`·`camera_key` 중
하나라도 바꾸면 이 홀드아웃을 다시 만들어야 한다.**

**둘 다 채점한다** — 기존(비교 연속성) + 새것(정직한 신호).
어느 쪽에서만 이기느냐가 그 자체로 정보다.

## 6. 방법론 — 오늘 비싸게 배운 것

016 §4 의 목록에 이어서.

7. **임의로 고른 파라미터 하나에 결론이 걸리면 그 파라미터를 두 점 이상 게이트에 넣는다.**
   뭉갬 배율 k=4 만 걸었는데 k=8 에서 무승부가 나왔다.
8. **SE 를 사전 추정할 때는 가장 큰 성분의 분산부터 센다.** Video 분산을 빼고 계산해 3.8배 빗나갔다.
9. **게이트마다 유리/불리/무승부 세 경우를 전부 정의하고 진리표에 빈칸이 없는지 확인한다.**
10. **"바닥"을 만들 때 두 팔이 지는 오차가 같은 종류인지 확인한다.**
    한 번 틀렸고, **고치면서 같은 실수를 반복했다**(두 팔의 뭉갬 배율이 달랐다).
    **비교하려면 한 축만 달라야 한다.**
11. **새너티의 문턱은 값이 통과하는 자료형에 맞춘다.** float32 에 1e-6 을 요구해 멀쩡한 검사가 실패했다.
12. ⭐ **결과를 본 뒤에 설계한 측정은 "탐색적"이라고 라벨한다.** 확증과 탐색을 섞으면
    사후 합리화를 사전 등록으로 착각한다.
13. ⭐ **판정 기준을 적어 놓고 결과를 본 뒤에 다른 지표로 갈아타지 않는다.** 가장 부끄러운 실수다.
14. ⭐ **오라클을 뭉갠 것과 모델이 그 해상도로 만든 것을 같다고 놓지 않는다.**
    전자는 저주파 **내용이 정답**이고 후자는 **창작해야 한다**.
    **비판한 것과 같은 종류의 낙관을 반복하기 쉽다.**
15. **같은 함수를 import 해서 같은 값이 나오는 것은 검증이 아니다.**
16. ⭐ **대리 지표는 크기뿐 아니라 방향조차 믿을 수 없다.**
    픽셀 L1 과 채점 지표가 **같은 데이터에서 정반대**를 가리켰다.
17. ⭐ **문헌이 준 것을 우리 데이터로 확인하기 전에는 쓰지 않는다.**
    "우리와 거의 같은 대회"라고 적었지만 **채점 함수가 달랐고**, 그래서 이전되지 않았다.

**그리고 값을 한 것**

- **판정선을 결과 전에 고정한 것.** 근거 하나가 틀렸다는 게 사후에 드러났는데,
  미리 적어 뒀기 때문에 검증되고 정정될 수 있었다. 그리고 **Gate 0 이 사전 등록대로
  발동한 덕분에**, 2라운드가 대부분 철회된 지금도 노선 결정은 확증 근거를 유지한다.
- **대리 실험의 한계를 측정 전에 적어 둔 것.** 평균내기 대리실험이 실패했을 때
  "그러므로 폐기"로 가지 않을 수 있었다(그리고 실제로 실험할 값이 있었다).
- **적대적 검수를 두 번 건 것.** 2차가 치명 2건·중대 8건을 잡았고 거의 전부 옳았다.
  혼자였다면 잘못된 결론 둘이 그대로 C 설계서로 넘어갔을 것이다.
- **결론이 맞아도 근거가 틀렸으면 철회한 것.** 철회 안 했으면 3라운드를 안 돌렸을 것이고,
  8/3 검수에서 방어하지 못했을 것이다.

### 운영에서 데인 것 (내용이 아니라 배선. 그래도 시간을 많이 먹었다)

1. `set -euo pipefail` 아래에서 **없는 디렉터리에 `ls`** → 체인이 배너만 찍고 즉사.
   `mkdir -p` 후 `find` 를 쓴다.
2. **셸 cwd 가 상위로 리셋되는 일이 있다.** 상대경로 로그 리다이렉트가 조용히 실패해
   측정이 아예 안 돌았다. **긴 작업의 스크립트·로그 경로는 절대경로로.**

## 7. 남아 있는 미해결

- **모델이 어느 실패 모드에 떨어질지 모른다.** A-1(방향 섞임)이면 어떤 설정으로도 지고,
  A-2(세기만 약함)면 25% 로도 이긴다. **오라클로는 절대 알 수 없다. 학습해야 안다.**
- **`blur_residual` 이 "모델의 저해상도 출력"의 타당한 대리값인지 검증되지 않았다.**
  독립 구현과 20.52% 차이. 해상도 결론의 크기가 여기 걸려 있다.
- **VRAM·처리량 예산표가 없다.** 320×512 × 16프레임 × 배치 N 에서 5090 이 감당하는 크기.
  해상도를 설계 변수로 다루려면 숫자가 필요하다.
- **로컬 → eval 이전은 여전히 미지수.** 016 §5 가 방향까지 어긋난 전례를 남겼다.
  **8/4 부터 매일 제출해 리더보드에서 확인하는 것이 유일한 길이다.**
- **제출 CSV 를 아직 C 로 만들어 본 적이 없다.** 배선은 살아 있으나 C 출력으로는 미검증.
