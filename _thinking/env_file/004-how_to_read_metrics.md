## 2. 매 500스텝 자동으로 찍히는 것 — 감시 계기판

점수가 아니다. **학습이 무너지는지만 본다.** 전부 순수 torch 로 잰다(킷 미사용).
로그에서 `[감시 8500] …` 줄이 이것이다.

| 이름 | 무엇을 재나 | 방향 | 문턱 |
|---|---|---|---|
| **코사인** | 예측 잔차가 정답 잔차와 **같은 쪽을 가리키나**. −1~+1 | ⬆ **높을수록 좋다** | 필요 0.96 |
| 뒤섞기 | 행동을 표본끼리 **섞어** 넣었을 때의 코사인 | 비교 기준선 | — |
| **Δcos** | 코사인 − 뒤섞기 = **행동이 실제로 기여한 몫** | ⬆ **높을수록 좋다** | ≥ 0.046 (G2) |
| 잔차비 | 예측 잔차 크기 ÷ 정답 잔차 크기 | **좋고 나쁨 없음** | ≥0.05 (G1, 1회성) |
| 프로파일기울기 | 뒤 프레임일수록 잔차가 커지나 | ⬆ **양수 유지** | > 0 |
| FiLM시간코사인 | 16프레임의 행동 변조가 하나로 뭉쳤나 | ⬇ **낮을수록 좋다** | < 0.90 |
| ρ중앙값 | 행동을 키우면 출력도 커지나 | (판정에서 강등) | — |
| loss | L1 + λ_c·(1−코사인) + 0.1·L_reg | ⬇ 낮을수록 좋다 | — |

### 함정 넷 — 이걸 모르면 오독한다

**① 잔차비는 품질 지표가 아니다.**
크기는 추론 때 λ 가 흡수한다. 0.05 를 넘어 "잔차가 죽지 않았다"만 확인하는 용도다.
1.3 이라고 좋은 것도 나쁜 것도 아니고, **λ 를 낮추라는 신호**다(§4).

**② ρ 는 못 쓴다.**
학습 **2스텝**짜리 모델도 ρ=+1.00 이 나왔다 — FiLM 이 행동에 매끄러워 어떤 신경망이든
구조적으로 단조다. `gates.py` 가 판정에서 뺐다. 완전 단절(0 이하)만 잡는다.

**③ 프로파일기울기가 통과해도 안심 못 한다.** `[측정 2026-08-09]`
팔이 **흐려지기만 해도** 뒤 프레임일수록 잔차가 커져서 통과한다.
이 지표는 "안 움직인다"를 **못 잡는다.** 실제로 통과하는 내내 그림이 죽어 있었다.

**④ FiLM시간코사인은 정의가 한 번 바뀌었다.**
커밋 `888fcf0` 이 DC(프레임 공통 성분) 제거 후 재도록 고쳤다. 같은 체크포인트에서
**구 0.990 vs 신 0.688** 이다. **2026-08-08 18:09 런의 값과 그 이후 런의 값을 직접 비교하지 마라.**

## 4. ⭐ λ — 제출 직전에 고르는 숫자 하나

λ 는 **학습과 무관하다.** 추론할 때 잔차에 곱한다.

```
출력 = 첫프레임 + λ × 예측잔차

λ=0     정지영상과 **비트 단위로 같다** (점수 0.30325).  하방이 봉쇄된다
λ=0.4   40% 만 반영
λ=1.0   모델이 낸 크기 그대로
```

**최적 λ 는 계산으로 나온다** — 감시 두 값만 있으면 된다:

```
λ* = 코사인 ÷ 잔차비
남는 오차(λ) = 1 − 2λ·코사인·잔차비 + λ²·잔차비²        (1.0 = 정지영상과 같음)
최소값 = 1 − 코사인²
```

`[측정 2026-08-09, step 8500: 코사인 0.493 · 잔차비 1.308 → λ* = 0.38]`

| λ | 남는 오차 | |
|---:|---:|---|
| 0.0 | 1.000 | 정지영상 |
| **0.4** | **0.758** | 최적. 정지영상보다 24% 낫다 |
| 0.7 | 0.935 | 겨우 6% 낫다 |
| **1.0** | **1.420** | **정지영상보다 42% 나쁘다** ❌ |

**⇒ 영상을 볼 때도 제출할 때도 λ=1 을 기본값으로 쓰지 마라.** 잔차비가 1 을 넘으면
λ=1 은 과잉이다.

⚠ 이건 **픽셀 L2** 기준이다. 리더보드는 DINO·Video·Action 이라 최적 λ 가 정확히 같지 않다.
그걸 재는 것이 **λ 스윕 제출**(008 §9-b)이고 아직 0회다. 다만 **0.3~0.5 를 스윕해야지
0.7~1.0 을 스윕하면 안 된다**는 것은 확정이다.

## 5. 필요할 때만 돌리는 탐침 둘

### `probe_erase_vs_draw.py` — 잔차를 부호로 쪼갠다

정답 잔차가 음수인 곳(물체가 **떠나는** 자리)과 양수인 곳(**도착하는** 자리)에서 따로 잰다.

```
cos⁻ · cos⁺   각 자리에서의 방향 정확도       ⬆ 높을수록 좋다
amp⁻ · amp⁺   각 자리에서 낸 세기 ÷ 필요 세기  → 1 에 가까울수록 좋다
```

`[측정 step 7000]` cos⁻ +0.326 / cos⁺ +0.555 · amp⁻ 0.477 / amp⁺ 0.655

⚠ **이 지표만으로 "새 자리에 그린다"고 읽으면 안 된다.** 옛 자리를 흐리게 뭉개기만 해도
가장자리에 양(+) 잔차가 생겨 cos⁺ 가 올라간다. §5-b 가 그 구멍을 메운다.

### `probe_does_it_move.py` — 무게중심이 어디로 가나

```
이동비    ‖예측 무게중심 이동‖ ÷ ‖정답 무게중심 이동‖   → 1 에 가까울수록 좋다
방향코사인 두 이동 벡터가 같은 쪽인가                   ⬆ 높을수록 좋다 (0 = 무작위)
판정선    이동비 ≥ 0.5 AND 방향코사인 ≥ 0.5
```

`[측정 step 8500]` 이동비 0.848 · **방향코사인 +0.220** → ❌ 미달
상위 10% 픽셀만 봐도 방향 +0.130 으로 같다.

**⇒ 잔차 덩어리가 움직이긴 하는데 방향이 거의 무작위다.** 그래서 화면에서는
"제자리에서 흐려지는" 것으로 보인다. 이게 지금 이 노선의 핵심 미해결 문제다.
